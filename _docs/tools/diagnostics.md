# 診断、警告、エラーの読み方

[ドキュメントのトップ](../README.md)

診断はコード、メッセージ、ファイル、ソース位置を持ちます。check / build / run は可能な範囲で独立した複数の問題をまとめて報告し、壊れたプログラムのコード生成や実行へは進みません。

## 最初に見る情報

```text
Main.tz:5:7: error[E1003]: expected i64, found bool
```

パスは実際に問題があるモジュールです。型不一致なら関数のシグネチャ、直前の let の型、数値の接尾辞を確認します。所有権のエラーなら、問題の使用より前の move や生きている借用を探します。

修正時はまず原因となる宣言を直します。壊れたシグネチャから派生する使用箇所の二次エラーは抑制されるので、最初の修正後に新しい診断が見えることがあります。

## JSON lines

```sh
./target/release/tsuzuri check examples/hello/Main.tz --json
```

診断は stderr へ一行一オブジェクトで出し、JSON 配列ではありません。失敗時の形式例です。

```json
{"severity":"error","code":"E1003","message":"expected i64, found bool","path":"Main.tz","span":{"start":17,"end":25,"line":1,"column":18,"end_line":1,"end_column":26}}
```

start / end は UTF-8 の byte offset で、end は排他的です。line / column は 1 始まり、column は Unicode の文字数で、タブも一文字です。LSP の UTF-8 / UTF-16 position とは同じ単位ではありません。

## エラーコード

| コード | 主な原因と確認先 |
| --- | --- |
| E0001 | 不正な字句、文字・数値リテラル |
| E0002 | 構文、式の深さ、誤配置の doc comment |
| E0003 | ソースサイズ上限 |
| E1001 から E1010 | 名前重複、型、演算、引数、フィールド、ABI、リテラル、レイアウト |
| E1011 | モジュール・package・path・予約名などの不正 |
| E1012 | move 後の使用、不正な move や代入 |
| E1013 | 寿命、格納できない借用、Task / 並列境界の借用 |
| E1014 | 借用競合、不変値への可変アクセス |
| E1015 | 曖昧な型、kind、不正な多相性、未確定の参照操作 |
| E1016 | 型クラスやインスタンスの不正・重複 |
| E1017 | 型展開、制約、特殊化、探索などの資源制限 |
| E1018 | ファイル種別、ビルダー操作、未対応の GPU 構造など |
| E1019 | rec / and と再帰グループの不整合 |
| E1020 | 不正なパターン・OR 束縛・認識器・case payload |
| E1021 | match / 関数ガードの網羅性不足 |
| E1022 | private や不透明型への不正アクセス、private 型の漏れ |
| E1023 | 不正な break / continue |
| E1024 | 型パラメーター、型別名、union の宣言不整合 |
| E1025 | 導出できない型クラス・要素・再帰 Default |
| E1026 | 定数の循環、トラップ、上限、未対応式 |
| E1027 | 条件付き instance、superclass、default method の制約不整合 |
| E2000 | CLI、オプション、拡張子 |
| E2001 | 入出力 |
| E2002 | LLVM や linker など外部ツール |
| E2003 | 出力保護 |
| E2004 | 入口条件 |
| E2005 | 実行時の異常終了 |
| E2006 | 言語内テストの失敗 |

特に E1003 は型不一致、E1005 は使用できない演算・呼び出し、E1007 はフィールド、E1008 は ABI、E1010 は値レイアウトを確認します。コードだけで全原因を判別せず、メッセージと位置も読みます。

## 警告

| コード | 対象 |
| --- | --- |
| W1001 | 未使用のローカル、引数、パターン束縛 |
| W1002 | 公開 API などから到達しない private 宣言 |
| W1003 | 先行節に覆われる到達不能な match 節 |
| W1004 | 同じ字句スコープの shadowing。内部オプションのみ、既定無効 |
| W2001 | cache I/O などツール側の警告 |

意図的な未使用ローカルは `_` または `_name` で明示します。move、借用、ガード、捕捉も使用として数えます。コンパイラ生成の束縛や std の未使用警告は利用者へ出しません。

既定で警告は終了コードを変えません。check / build / run の `--deny-warnings` は警告だけでも終了コード 1 にして、コード生成や実行の前に停止します。JSON の severity は warning のままです。

ソースエラーがある場合には警告を出しません。警告が表示されないことだけで、すべての unused 検査が済んだと判断しないでください。

## 複数診断の範囲

ファイル・位置・コード・メッセージの安定した順に並べ、同じ診断は重複表示しません。表示は 50 件まで、収集は重複しない 1,000 件までです。残りは正確な件数、収集上限に達した場合は下限として通知します。

字句エラーのファイルは構文検査へ進めず、構文エラーのあるプロジェクトは型検査へ進みません。

一つの関数やトップレベルの実行式でも、部分式・引数・型注釈から回復して独立した型エラーを集めます。壊れた値から派生する二次エラーは抑制します。移動済みの使用・可変アクセス・借用競合は、元の値ごとに最初の一件を報告して続けます。

型エラーがある場合も、型を確定できた本体の移動済みの使用・可変アクセス・借用競合を報告します。寿命などその他の所有権エラーは、偽のエラーを防ぐため型の修正後に報告します。修正後に残りのエラーが見える場合があり、全問題の報告は保証しません。

本体前の領域・制約・計算式展開の失敗、資源制限の E1017、収集上限は本体を打ち切ります。回復した本体の型確定・網羅性の二次エラーは報告せず、アクセス以外の所有権エラーも本体の最初の一件で止めます。構文の文単位の回復と、回復した本体の意味索引は未対応です。

生成・リンクに失敗した場合も既存出力を維持します。CLI、入力読み込み、外部ツール、実行時の失敗は単一診断となる場合があります。
