# 式、演算子、評価順序

[ドキュメントのトップ](../README.md)

Tsuzuri は厳格評価の式指向言語です。ブロックの最後の式が値になり、評価順序とトラップを最適化で暗黙に変更しません。

## ブロックの結果

```tsuzuri run=42
def calculate :: i64 -> i64 = \value -> {
    let adjusted = value + 1;
    let adjusted = adjusted * 2;
    adjusted
}

calculate 20
```

同名の新しい束縛は以前の束縛を隠します。右辺は新しい名前を導入する前に評価するため、上の二つ目の adjusted は最初の adjusted を読めます。

最後の結果に `;` を付けると値を捨てます。最後の結果がないブロックは unit です。インデント本体の中間式には unit が必要です。

## 優先順位

低いものから順に示します。二項演算子はすべて左結合です。

| 順位 | 演算子・操作 |
| --- | --- |
| 1 | `\|>` |
| 2 | `\|\|` |
| 3 | `&&` |
| 4 | ビット OR `\|` |
| 5 | ビット XOR `^` |
| 6 | ビット AND `&` |
| 7 | `==`, `!=` |
| 8 | `<`, `<=`, `>`, `>=` |
| 9 | `<<`, `>>`, `>>>` |
| 10 | `+`, `-` |
| 11 | `*`, `/`, `%` |
| 12 | `as Type` |
| 13 | 単項 `-`, `!`, `~`、借用・参照外し |
| 14 | 関数適用、`.field`、`[index]` |

代入 `=` はすべての二項演算より低い優先順位です。型の矢印は右結合であり、上の式の二項演算とは別です。曖昧に見える式は括弧で意図を示してください。

`!` は bool の否定、`~` は整数のビット反転です。`>>` / `<<` は F# の関数合成ではなく整数シフトです。

## 評価順序

| 構造 | 順序 |
| --- | --- |
| 通常の二項演算 | 左、右 |
| 関数呼び出し | callee、その段階の各引数を左から右 |
| パイプ `value \|> transform` | value、transform、その後適用 |
| 配列・リスト | 要素を記述順に一度ずつ |
| レコード初期化 | フィールドの記述順。宣言順へ並べ替えない |
| 代入 | 右辺、代入先 |
| レコード更新 | 元値、更新値を記述順にすべて評価、構築、旧値の解放 |
| スライス | 元配列、開始、終了 |

カリー化の途中で本体を実行する関数では、その段階の処理を後続引数より先に実行します。callee が捕捉環境を持つ場合にも、その時点のスナップショットの意味を保ちます。

## 短絡

```tsuzuri run=42
let safe = false && (1 / 0 == 0)
let available = true || (1 / 0 == 0)
assert (!safe && available)
42
```

`&&`、`||`、if の未選択分岐は必要な部分だけを評価します。一方、通常の関数は厳格評価です。例えば `default_value fallback option` の fallback は、使われなくても先に評価されます。

値を捨てる束縛、未使用の結果、length の取得なども、必要な引数の評価やトラップを省略するという言語上の指示ではありません。

## 演算子と型クラス

加算は Add、比較は Eq / Ord、ビット演算は Bits などに対応します。同名関数のオーバーロードによる探索ではありません。型の組み合わせが合わない場合、暗黙変換で合わせることはありません。

比較は共有借用で非消費、通常の算術・文字列連結は値を受け取ります。この違いは独自インスタンスでも守る必要があります。
