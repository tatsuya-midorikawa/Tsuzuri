# Tsuzuri 0.1 言語仕様

初版は **ファイル単位のモジュール、単相、厳格評価、所有権と借用を持つ式指向言語** です。
値の計算と所有するローカル状態を対象とし、OS／GUI／DOM／ネットワーク／ファイル I/O はホスト側に置きます。
可変状態へのアクセスには排他的な借用を要求し、共有可変状態は導入しません。
非停止、スタック枯渇、検査違反によるトラップはあり、全関数の停止は保証しません。
コンパイル時に扱えない構文・型を、別の意味へ暗黙に置き換えることはありません。

## ソースと宣言

- `.tzr`、UTF-8、先頭 BOM、LF／CRLF。識別子は ASCII の英字または `_` に続く英数字／`_`。
- `//` 行コメントと、入れ子可能な `/* ... */` コメント。
- 関数内では空白と改行は同等。インデントに構文上の意味はありません。
- 宣言は `record`、`fn`、`export fn`。宣言順・ファイル順によらず参照でき、モジュール間の相互再帰も可能です。
- `Main.tzr` に限り、宣言の後にトップレベルの `let` と最後の結果式を書けます。
- ソースは **1 ファイルごとに最大 1 MiB**、構文と式の深さは最大 128。長い式は `let` で分割します。

### 1 ファイル = 1 モジュール

各 `.tzr` ファイルは、拡張子を除いたファイル名と同じ名前のモジュールを一つだけ定義します。
モジュール名は大文字小文字を区別する ASCII 識別子で、`_` 単独や字句上の予約語は使えません。
`module`／`namespace` 宣言、入れ子のモジュール、同じモジュールの複数ファイルへの分割はできません。
ファイル内のレコードや関数の数に「一つだけ」という制約はありません。

コンパイラは入力ファイルと同じディレクトリ直下の **全 `.tzr` ファイル** を名前順に読み込み、
一つのプロジェクトとして検査・コンパイルします。未参照のモジュールも検査対象です。
ディレクトリを入力すると、その直下の `Main.tzr` を選びます。
インポート宣言や CLI での複数ソースの列挙は不要です。
サブディレクトリの再帰探索、外部パッケージ、検索パスはありません。

`Point.tzr`:

```text
record Point { x: f64, y: f64 }

fn distance(point: Point) -> f64 {
    sqrt(point.x * point.x + point.y * point.y)
}

export fn hypotenuse(x: f64, y: f64) -> f64 {
    distance(Point { x: x, y: y })
}
```

同じディレクトリの `Main.tzr`:

```text
let p = Point { x: 10.0, y: 20.5 }
let d = Point.distance(p)
```

`Point.tzr` 内では `distance(p)`、他のファイルでは `Point.distance(p)` と書きます。
`Point.distance` は関数値としても使え、高階関数の引数や `p |> Point.distance` にも対応します。
関数の名前空間はモジュールごとに独立し、別モジュールの同名関数は衝突しません。
他モジュールの関数を無修飾では参照できません。
ローカル変数がモジュールと同名の場合、`name.field` はローカル値のフィールドアクセスを優先します。

レコード型・リテラルは `Point.Point` のような修飾名を常に使えます。
無修飾の `Point` はまず自モジュールで解決し、なければプロジェクト内で一意なレコード名を解決します。
他モジュールに同名レコードが複数ある場合は修飾が必要で、曖昧な名前はエラーです。
同じフィールドを持つ同名レコードでも、所属モジュールが違えば別の型です。

**`export` は C／WASM ホストへの公開指定で、モジュール間の可視性とは無関係です。**
上の `distance` のような通常の `fn` も他モジュールから呼び出せます。
レコード・配列・関数値をモジュール間で渡すこともできます。
`export fn` のスカラー ABI 制限はホスト境界にだけ適用します。

関数の引数と返却型、レコードのフィールド型は明示します。ローカルな `let` は型推論します。
オーバーロード、暗黙の数値変換、可変引数、モジュール共有の状態、外部関数宣言はありません。
組み込み関数名はトップレベル関数の名前として再定義できません。

### アプリケーションのエントリーポイント

`run` とネイティブ実行ファイルのビルドは **`Main.tzr` またはそのディレクトリ** を入力にします。
他ファイルの `fn main` は通常の関数であり、エントリーポイントとして選択されません。
`Main.tzr` では次のどちらか一方を使います。

- 宣言の後にトップレベルの `let` を順に書き、必要なら最後に結果式を書く。
- 引数なしで数値型／`bool`／`unit`／`string` を返す `fn main` を定義する。

トップレベルの `let` の区切りは `;`、改行、またはファイル末尾です。
右辺を次の行へ続ける場合は演算子の直後で改行するか、括弧・配列・レコード・ブロックの内側に書きます。
例えば `let x = 40` の次の行に `(x + 2)` や `-x` を書くと、別の結果式になります。
関数・ブロック内の `let` では従来どおり `;` が必須です。
トップレベルの束縛はエントリーコード内のローカル値で、宣言済み関数からの参照や
他モジュールへの公開はできません。右辺をソース順に評価し、結果式がなければ `unit` を返します。
上の `Main.tzr` は何も表示しません。末尾に `d` を追加すれば距離を表示します。
結果式がある場合、その型は数値型／`bool`／`unit`／`string` に限り、
ネイティブのホスト・ラッパーが値を表示します。文字列は埋め込み NUL を含め UTF-8 のバイト列を出力します。

トップレベルの実行コードと `fn main` の併用、他モジュールでのトップレベル実行はエラーです。
`check` とライブラリ出力は `Point.tzr` なども入力にでき、`Main.tzr` は不要です。
ライブラリ／WASM 出力はホストの `export fn` 呼び出しで実行し、トップレベルのエントリーコードを自動実行しません。

## 型とメモリ

| 型 | 値／挙動 |
|---|---|
| `bool` | `true` / `false` |
| `unit` | `()` または空ブロック `{}` |
| `i8` / `i16` / `i32` / `i64` / `i128` | 指定幅の符号付き整数 |
| `i8u` / `i16u` / `i32u` / `i64u` / `i128u` | 指定幅の符号なし整数 |
| `f16` / `f32` / `f64` / `f128` | IEEE 754 binary16 / binary32 / binary64 / binary128 |
| `d32` / `d64` / `d128` | IEEE 754 decimal32 / decimal64 / decimal128（BID エンコーディング） |
| `byte` / `ubyte` | それぞれ `i8` / `i8u` の別名 |
| `string` | 所有する不変の UTF-8 文字列 |
| `Point` など | 名前付きの不変レコード。フィールド数・型は宣言通り |
| `[i32; 4]` など | 要素型・長さが静的に決まる不変配列 |
| `fn(i32) -> i32` など | 名前付き関数／組み込み関数への静的参照 |
| `&T` / `&mut T` | 共有借用 / 排他借用。所有者の寿命を超えて保持できない |

旧名 `Int`／`Float`／`Bool`／`Unit` は組み込み型ではありません。
GC、参照カウント、手動の解放操作は使わず、所有権と借用によりメモリを管理します。
レコードと配列は値として保持し、LLVM がスカラー化やコピー除去を行います。
大きな値のコピーまで常に無償になるわけではありません。
配列は 0～1024 要素、値の保守的なレイアウト上限は 64 KiB
（スカラーを 8 バイト以上、128-bit 値と文字列を 16 バイト、レコードの各フィールドを
16 バイト境界に切り上げて計算）です。文字列のバッファ本体はこの値レイアウトに含めません。
相互参照や長さ 0 の配列経由も含め、無限になるレコードの値レイアウトを拒否します。
関数参照は静的なコードへの参照なので、循環した値レイアウトにはなりません。

### Ownership / Borrowing

各所有値の所有者は一つです。`string` と文字列を含む集約値は、束縛・引数・結果として
値を渡すと **move** します。移動元を再使用すると `E1012` です。
所有する文字列バッファはスコープ終了時に自動解放されます。
関数引数は呼び出された関数が所有し、戻り値は呼び出し元へ所有権を移します。
レコードからのフィールド単位の move も可能で、残りのフィールドは引き続き使え、個別に解放されます。
非 Copy 要素を配列から取り出す move と、参照を通じた非 Copy 値の move はできません。

数値、bool、unit、静的関数参照、`&T` は **Copy** です。
レコードと配列は、全フィールド／全要素が Copy なら自動的に Copy になります。
Rust の明示的な `derive(Copy)` と異なり、宣言による opt-in は不要です。
`&mut T` は Copy ではありません。

```text
fn length(text: &string) -> i64 { text.length }
fn identity(text: &string) -> &string { text }
fn replace(text: &mut string) -> unit { *text = "next"; }

fn example() -> string {
    let mut text = "前の値";
    let shared = identity(&text);
    let size = length(shared);
    replace(&mut text);       // shared の最終使用の後なので借用できる
    let owned = text;         // move
    owned
}
```

`&place` は共有借用、`&mut place` は排他借用、`*reference` は参照先の値です。
共有借用は複数保持できますが、排他借用中は同じ所有者への他のアクセスを拒否します。
`let mut name = value;` または `fn f(mut name: T)` で所有する束縛を可変にできます。
`name = value;`／`*reference = value;` は値全体を置換し、旧所有値を解放します。
代入式の型は unit、評価順序は右辺、代入先です。`let` の既定は引き続き不変です。
可変参照自身の束縛は、参照先を置換するだけなら `mut` である必要はありません。
レコードのフィールド・配列の要素・文字列のバイトを直接書き換えることはできません。

排他参照を一時的に貸し直す場合は `&mut *reference`、読み取り用なら `&*reference` と書きます。
貸し直した参照の生存中は元の排他参照を使用・移動できません。
参照は後続の使用がなくなれば借用を終えられますが、分岐の合流や配列要素の別名関係は保守的に検査します。
いずれかの分岐で move した値は合流後に使えません。排他参照を引数にそのまま渡すと move し、
Rust のような暗黙の reborrow は行いません。

借用を返す関数では、借用を含む入力を一つだけ要求し、その入力に戻り値の寿命を結び付けます。
ローカル所有値への参照、ブロックを抜けると無効になる参照、寿命を超える代入を拒否します。
名前付きライフタイム、借用フィールドを持つレコード、一般的な入れ子参照の寿命推論、
一時値の借用と寿命延長は未対応です。一時値は先に `let` で所有者へ束縛してください。
Rust の所有権モデルを採用したサブセットであり、Rust の全構文・trait・ライフタイム機能との互換ではありません。

### UTF-8 文字列

`"こんにちは"` のように記述し、`\"`、`\\`、`\n`、`\r`、`\t`、`\0`、
Unicode スカラーの `\u{1f600}` に対応します。不正なエスケープやサロゲートを拒否します。
`string.length` は UTF-8 の **バイト数** を i64 で返し、`text[index]` は ubyte を返します。
添字の範囲外はトラップします。文字／書記素単位の索引ではありません。
`+` は両辺の所有権を消費して連結し、`==`／`!=` は所有権を消費せずバイト列を比較します。
コピーが必要なら `clone_string(&text)` で独立した所有値を作ります。
文字列操作でも左から右の評価順序を維持し、比較・索引の途中で所有者を無効化する操作は借用エラーです。

```text
fn square(x: i64) -> i64 { x * x }
fn apply(f: fn(i64) -> i64, x: i64) -> i64 { f(x) }
fn choose(flag: bool) -> fn(i64) -> i64 {
    if flag { square } else { identity }
}
fn identity(x: i64) -> i64 { x }
```

関数値は引数、戻り値、レコード、配列に格納できます。キャプチャ付き／匿名ラムダ、
部分適用、カリー化、ジェネリクスは初版にはありません。

## 式と評価順序

```text
fn calculate(value: i64) -> i64 {
    let offset: i64 = 2;
    let adjusted = value + offset;
    let adjusted = adjusted * 2;
    if adjusted > 0 { adjusted } else { 0 }
}
```

`let name [: Type] = expression;` は不変のローカル束縛です。
同名の新しい束縛によるシャドーイングは可能ですが、既存の値は変わりません。
右辺は新しい束縛の導入前に評価します。`_` は値を評価して捨てる名前で、参照はできません。
ブロックは最後の式の値を返し、最後の式がなければ `unit` です。
最後の結果式には `;` を付けません。`;` を付けた式は値を評価して捨てます。
代入は可変の所有束縛または排他参照を通じてのみ許されます。ループ文はありません。

`if condition { a } else { b }` は条件が `bool`、両分岐は同じ型でなければなりません。
実行するのは選ばれた分岐だけですが、両方を型検査します。`else` は必須です。
`else if` の連鎖も使えます。条件内のレコードリテラルは括弧で囲んでください。

通常の二項演算、関数呼び出しの callee → 各引数、配列要素、
レコードの初期化フィールドは **ソースに書かれた順に左から右** へ評価します。
`a |> f` は `a`、`f` の順に評価し、一引数の `f` を呼び出します。
`&&` と `||` は短絡評価です。
結果を捨てる `let` や `.length` でも、必要な引数評価やトラップを省略する意味にはなりません。

### 配列とレコード

```text
fn first(values: [i64; 3]) -> i64 { values[0] }
fn empty() -> [i64; 0] { [] }
fn length() -> i64 {
    let values = [10, 20, 30];
    values.length
}
```

配列の添字は `i64`。負値や `length` 以上の添字はトラップします。
空配列は、戻り型・引数型・`let` の型注釈などから要素型が決まる場合に書けます。
各要素は同じ型で、動的な伸縮や要素の代入はありません。
レコードリテラルは全フィールドをちょうど一回ずつ指定し、並び順は任意です。
レコード・配列・関数の `==` は初版にはありません。

### 演算子

優先順位は低いものから次の通りです。二項演算はすべて左結合です。

| 順位 | 演算子 |
|---|---|
| 1 | `\|>` |
| 2 | `\|\|` |
| 3 | `&&` |
| 4–6 | `\|`、`^`、`&` |
| 7 | `==`、`!=` |
| 8 | `<`、`<=`、`>`、`>=` |
| 9 | `<<`、`>>`、`>>>` |
| 10 | `+`、`-` |
| 11 | `*`、`/`、`%` |
| 12 | 数値変換 `as Type` |
| 13 | 単項 `-`、`!`、`~`、`&`、`&mut`、`*` |
| 14 | 関数呼び出し、`.field`、`[index]` |

`==`／`!=` は同じスカラー型、unit、string、大小比較は同じ数値型、
論理演算は bool、ビット演算と `%` は同じ整数型に対して使えます。
`=` はすべての二項演算より低い優先順位です。

## 数値仕様

整数リテラルは十進、`0x` 十六進、`0b` 二進に対応し、桁の間に `_` を使えます。
浮動小数点リテラルは `1.5`、`1e3`、`1.2e-3` など。
型注釈、関数の引数・結果、演算の相手から型を決めます。接尾辞による `127i8`、
`340282366920938463463374607431768211455i128u`、`1f16`、`0.1d128` も使えます。
型を決める文脈も接尾辞もなければ、従来の幅を維持して整数は i64、小数点／指数付きは f64 です。
`let` の型推論は右辺で完結し、後の使用から型を逆推論しません。
整数と浮動小数点の間、および異なる型の変数の間に暗黙変換はありません。
範囲外の整数リテラルと、無限大に丸められる浮動小数点リテラルはコンパイルエラーです。
各符号付き整数型の最小値も負のリテラルで記述できます。
binary リテラルは目的の幅へ直接丸め、f64 を経由して f128 の精度を失うことはありません。

- 整数の `+ - *`、符号反転、ビット演算は指定されたビット幅で折り返します。
- 符号反転は符号付き整数と浮動小数点に使えます。符号なし整数への単項 `-` はエラーです。
- `/` はゼロ方向への切り捨て、`%` は被除数と同符号の剰余です。
- 整数のゼロ除算、および最小値の `-1` による除算・剰余はトラップします。
- シフト数は `count & (bit_width - 1)`。符号付きの `>>` は算術右シフト、
  符号なしの `>>` とすべての `>>>` は論理右シフトです。
- 全浮動小数点型は NaN、無限大、符号付きゼロ、非正規化数を保持し、最近接・偶数丸めを使います。
  NaN のペイロード、浮動小数点例外フラグ、丸めモードの変更は公開しません。
- NaN に対する `==`／大小比較は false、`!=` は true。浮動小数点のゼロ除算は IEEE 754 通りです。
- decimal32／64／128 の有効桁は 7／16／34 桁、調整後の指数の範囲は
  -95～96／-383～384／-6143～6144。最小の非ゼロ値は 1e-101／1e-398／1e-6176 です。
  f16／f128 と decimal は同梱の整数ベース演算で処理し、binary64 で代用しません。
- fast-math、許可されていない再結合、暗黙の FMA は使いません。ホストの標準の丸め環境を前提とします。

`value as Type` は数値型の明示的な変換です。整数の縮小は下位ビットを保持し、拡大は
変換元の符号に従って拡張します。浮動小数点への変換は目的の基数・精度に最近接・偶数丸めし、
浮動小数点から整数への変換はゼロ方向に丸め、範囲外は飽和、NaN は 0 です。
binary／decimal 間も直接変換できます。

### 組み込み関数

| 名前 | 型／意味 |
|---|---|
| `sqrt` | `fn(f64) -> f64`。負数には NaN |
| `floor`、`ceil` | `fn(f64) -> f64` |
| `abs` | `fn(f64) -> f64`。i64 用ではない |
| `to_float` | `fn(i64) -> f64`。大きな整数では丸めが発生する |
| `to_int` | `fn(f64) -> i64`。ゼロ方向に丸め、範囲外は飽和、NaN は 0 |
| `assert` | `fn(bool) -> unit`。false ならトラップする部分関数 |
| `clone_string` | `fn(&string) -> string`。独立した UTF-8 バッファを持つ所有値を作る |

数値の組み込み関数は上記の固定シグネチャを維持しており、オーバーロードではありません。
その他の数値型の変換には `as` を使います。
コンソール表示は f32 が最大 9 桁、f64 が最大 17 桁、f16／f128 が最大 36 桁で、
decimal は値を十進で正確に表示します。末尾の不要なゼロは省略します。

トラップは WASM では `WebAssembly.RuntimeError`。
ネイティブでは `llvm.trap` によるプロセス終了です。
`tsuzuri run` は異常終了を診断しますが、言語内の回復可能な例外機構はありません。
UI／公開 API の入力はホストでも検査してください。
メモリ確保失敗もトラップします。トラップ時のスタック巻き戻しや destructor 実行は保証しません。

## 再帰とスタック

自己への直接の呼び出しが関数の結果になる場合、LLVM IR の phi とループへ変換します。
末尾のブロック／if 内、`value |> self` も対象です。
引数は全て元の値から計算した後に一度に更新します。
これは LLVM の最適化レベルに依存しません。次の反復へ移動しなかった所有値は分岐前に解放します。
借用を含む引数を持つ関数では、参照先のフレームを再利用しないため、このループ変換を行いません。

関数値経由の再帰、相互再帰、呼び出した後に演算が続く再帰には、定数スタックの保証はありません。
ネイティブのスタック上限は OS に依存します。
WASM は stack-first 配置で 1 MiB のスタック、線形メモリ上限 16 MiB を設定します。
文字列バッファはスタック・静的領域の後のヒープへ確保し、解放済み領域を再利用・結合します。
ネイティブでは malloc/free を使います。WASM の呼び出しスタック上限は実行エンジンに依存します。
配列の一時領域は関数の入口で確保するので、末尾ループの反復で蓄積しません。

## 公開 ABI

`export fn name` の公開シンボルはネイティブ／WASM ともに `tz_name`。
接頭辞によって C の予約語・`main`・C ランタイムとの名前衝突を避けます。
既存の ABI を維持するため、`export fn` の名前はプロジェクト全体で一意でなければなりません。
通常の関数名はモジュールごとに同名を使えますが、同じ `tz_name` を公開する複数の宣言はエラーです。
内部関数／レコードの LLVM 表現は安定 ABI ではありません。

| Tsuzuri | C ヘッダー | WASM / JavaScript |
|---|---|---|
| `i8` / `i16` / `i32` | `int32_t` | i32 / `Number` |
| `i8u` / `i16u` / `i32u` | `uint32_t` | i32 / `Number` |
| `i64` / `i64u` | `int64_t` / `uint64_t` | i64 / `BigInt` |
| `f32` / `f64` | `float` / `double` | f32 / f64 / `Number` |
| `bool` | `int32_t` | i32 / `Number` |
| `unit`（返却値のみ） | `void` | 返却値なし / `undefined` |

bool 引数の 0 は false、非 0 は true。結果は 0/1 に正規化します。
8／16-bit 整数は ABI 境界で下位ビットへ切り詰め、返却時に符号／ゼロ拡張して i32 に正規化します。
WASM の i32／i64 の JavaScript 返却値は符号付きとして見えるので、必要なら
`value >>> 0`／`BigInt.asUintN(64, value)` で符号なしに解釈してください。
`i128`／`i128u`、f16／f128、decimal、string、参照、unit の引数、
レコード、配列、関数値はエクスポートできません。これらの型もモジュール内部・モジュール間では使用できます。
公開値にホストのポインターや寿命管理を要求しないための初版の制約です。
ホストからアクセス可能な線形メモリが出力に含まれていても、そのレイアウトは公開 API ではありません。

```sh
tsuzuri build Kernel.tzr --emit object -o kernel.o
tsuzuri build Kernel.tzr --emit header -o kernel.h
tsuzuri build Kernel.tzr --target wasm32 -o kernel.wasm
```

WASM は WASI、.NET、JavaScript の関数インポートを必要としません。
LLD により到達しないコードを削除します。
128-bit 整数の乗除算・剰余・可変シフトには同梱の補助関数を使い、
ホスト依存の compiler-rt を要求しません。

## 診断

成功時は終了コード 0、ソース／ツール／I/O／実行エラーは 1、CLI の引数構成の誤りは 2 です。
拡張子や通常ファイルでない入力の拒否もソースエラーとして終了コード 1 です。
検査は最初のエラーで停止します。安定したコードと位置を持ちます。
`check` は実行入口の有無・返却型や LLVM の有無を検査せず、
プロジェクト全体の構文・型・公開 ABI とファイル単位のモジュール規則を検査します。
エラーは入力ファイルにまとめず、実際に問題があるモジュールのパスとそのファイル内の位置を報告します。

```json
{"severity":"error","code":"E1003","message":"expected i64, found bool","path":"Main.tzr","span":{"start":17,"end":25,"line":1,"column":18,"end_line":1,"end_column":26}}
```

`start`／`end` は UTF-8 のバイトオフセット（end は排他的）。
行・列は 1 始まりで、列は Unicode の文字数です。タブも一文字として数えます。
`--json` の診断先は stderr。ツールの警告は `W2001` の JSON オブジェクトです。
一時領域を OS が削除できなかった際の最後のクリーンアップ警告は通常のテキストです。

| コード | 分類 |
|---|---|
| `E0001` / `E0002` / `E0003` | 字句／構文・深さ／ソースサイズ |
| `E1001`–`E1010` | 名前、型、演算、引数、フィールド、ABI、リテラル、レイアウト |
| `E1011` | 無効なモジュール名・重複モジュール |
| `E1012` | move 後の使用、不正な move／代入先 |
| `E1013` | 所有者を超える寿命、対応していない寿命表現 |
| `E1014` | 借用の競合、不変値への可変アクセス |
| `E2000` | CLI／オプション／拡張子 |
| `E2001` / `E2002` | I/O／LLVM ツール |
| `E2003` / `E2004` / `E2005` | 出力保護／入口条件／実行時の異常終了 |
