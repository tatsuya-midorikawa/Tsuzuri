# Program failed at run time

## What it covers
A program started by `tsuzuri run`, `tsuzuri script`, `tsuzuri repl`, or `tsuzuri bench` ended abnormally: a trap (a failed assertion, an index out of bounds, an integer division by zero, an overflow, ...), a nonzero result of `def main`, an exhausted stack, or a time or output limit. A benchmark that traps, times out, or measures a negative time is reported too.

## Fixes
- Read the trap reason and source position in the message (`tsuzuri run` enables `--trap-info`), and fix the operation there.
- Return 0 from `def main` on success; any other result is reported as a failure.
- Replace deep recursion with a loop or a tail call when the stack is exhausted.
- In the REPL, raise `--timeout`, or make the evaluation finish sooner.
- Build with `-g` and run the program under a debugger to inspect the failing state.
