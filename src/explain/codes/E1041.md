# An anonymous union is misused

## What it covers
An anonymous union `(A | B)` tells its members apart by their types alone.

- `anonymous_union_type_variable`, `anonymous_union_indistinct_members`, `anonymous_union_duplicate_member`: a member is a type variable, two members are equal for some type arguments (`Maybe<'a>` and `Maybe<i64>`), or a member repeats after aliases and nested unions are expanded. The location is the union type.
- `anonymous_union_ambiguous_literal`, `anonymous_union_ambiguous_member`: a value where the union is expected could be two members, as `16` in `(i32 | i64 | string)` or `None` in `(Maybe<i64> | Maybe<string>)`. No member is a default.
- `type_test_unknown_scrutinee`, `type_test_not_anonymous_union`: the value that `:?` tests has no known anonymous union type.
- `type_test_union`, `type_test_not_member`: the type after `:?` is a union, or no member.
- `anonymous_union_instance`: an `instance` names an anonymous union as its type.

## Fixes
- Remove the repeated member, or make the members concrete so that they differ without type arguments.
- Add a literal suffix such as `16i64`, or annotate the value with a typed `let`.
- Annotate the parameter or binding that `match` tests with its anonymous union type.
- Write one `:?` arm for each member, with a member type of the union.
- Declare a union with named cases, or wrap the union in a record, when cases hold a type variable or the same type, or need an instance.
