# Effect attribute broken by the inferred summary

## What it covers
A function marked `@no_alloc`, `@no_copy`, `@no_trap` or `@terminates` has an effect summary that holds what the attribute promises to be absent: a heap allocation, an implicit copy of every element, a trap of the program's logic, or a loop or recursion that may not end. The location is the expression in the function, or the first call that leaves it toward the effect. An `extern` call breaks `@no_alloc`, `@no_trap` and `@terminates`, and a call that the analysis cannot follow (`dyn`, or a function value that the caller chooses) breaks every attribute. So does a use, as a value, of an attributed function that calls its parameters before they are supplied.

## Fixes
- Remove the expression or call that the message names, or change it as its help says.
- Borrow arrays and lists with `ref` instead of copying them.
- Guard an index with `if i >= 0 && i < xs.length`, or use `Array.try_item` and match the `Maybe`.
- Use `for` over a range or a collection instead of `while` or recursion.
- Pass a named function or a lambda, or add the same attribute to the function that forwards its parameter; call a function that calls its parameters, or store it with them applied.
- Remove the attribute when the function needs the effect.
