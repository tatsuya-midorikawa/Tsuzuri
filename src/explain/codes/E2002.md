# LLVM, linker, or external tool failure

## What it covers
A tool that the compiler runs after checking failed or could not start, such as Clang, the linker, or another LLVM tool. This includes unresolved symbols, a target that has no implementation of an operating-system, `Net`, or `Async` API that the program reaches, a Windows object that cannot embed the runtime, combinations that the bundled toolchain does not support, and constructs that `--backend fast` cannot translate.

## Fixes
- Read the tool's output in the message; give the linker the library that defines an unresolved symbol with `--link`, `-l`, or `-L`.
- Install LLVM/Clang 17 or later, or set `TSUZURI_CLANG` to a Clang executable.
- Build for a target that implements the API that the message names, or use the alternative it suggests, such as `Async.run`.
- For a Windows object, build an executable instead, or emit LLVM IR and link the runtime once.
- Build with `--backend llvm` when the fast backend cannot translate a construct, and report the program.
- Link MSVC targets on a Windows host; the bundled toolchain does not link them from other hosts.
