# Monoid of a type that holds a floating-point number

## What it covers
A `Monoid<T>` constraint is resolved for a concrete type `T` that holds a floating-point number: `f16`, `f32`, `f64`, `f128`, a decimal (`d32`, `d64`, `d128`), or a SIMD vector of them, directly or through record fields, union payloads, tuples, arrays, lists, `Vec` and `Maybe`. Floating-point addition and multiplication are not associative, so `Parallel.fold`, which combines chunks, could return different bits from `Array.fold_monoid`. The location is the call that needs the instance (`Array.fold_monoid`, `Parallel.fold`, `Monoid.combine`); an instance that no call uses is accepted.

## Fixes
- Accumulate in integers instead, in fixed point (for example `micros: i64` for an amount).
- Use `Parallel.sum` for a floating-point sum whose order is fixed by the chunk rule, or `Array.sum_pairwise` and `Array.sum_kahan` for a documented sequential order.
- Use `Array.fold` with a floating-point state when the order of the sequential fold is what you want.
