# Access to a private or opaque item

## What it covers
Code uses something that it may not see: a `private` declaration of another module, a private type in a public declaration, the representation of an opaque standard type (`Map`, `Arena`, `Mutex`, `Channel.Sender`, ...), or a builtin reserved for the standard library, such as `Os.__read`. `private` on a declaration that cannot be private is also reported.

## Fixes
- Call the module's public functions, or remove `private` from a declaration that belongs to the module's API.
- Make a type public when a public declaration uses it, or make that declaration `private` too.
- Build and read opaque standard types through their module's functions, not their fields.
- Use the public API instead of `__` builtins, for example `Alloc.snapshot` and `Alloc.since` instead of `Alloc.__counter`.
- Put `private` on the `def` signature, not on its implementation; type classes and instances are always public, and `private export` is not allowed.
