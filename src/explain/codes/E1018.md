# File kind, builder, or GPU kernel rule

## What it covers
A declaration is in the wrong kind of file (type classes belong in `.tt`, one computation builder in each `.tc`), a computation expression has no builder or uses an operation its builder does not define, a GPU kernel uses a type, operator, or construct that its output does not support, or a build reaches an API that its kind of output does not allow, such as `Bench.now` outside `tsuzuri bench` or `Alloc` without the counting allocator.

## Fixes
- Put type class declarations in a `.tt` file, each builder and its `@alias` in its own `.tc` file, and other declarations in `.tz` files.
- Define the builder operation that the message names (`Bind`, `Return`, `Yield`, `Zero`, ...).
- Name the builder explicitly (`Builder { ... }`) or annotate the result type when the builder cannot be inferred.
- Use only the element types and operators that the chosen GPU output supports, or the CPU reference path.
- Call `Bench.now` only from `bench` declarations, which run under `tsuzuri bench`; build with `--allocator counting` when the program uses `Alloc`.
