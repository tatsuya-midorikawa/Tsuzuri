# Capability that the manifests do not allow

## What it covers
The root `Tsuzuri.toml` declares a capability policy (`[capabilities]`, or `capabilities = [...]` on one of its dependencies), and a package's own code uses a capability outside what it may use: through a std function that reaches the host (`File` needs `fs`, `IO` and `Debug` need `stdio`, `Net` needs `net`, ...) or through an `extern` function (`ffi`). The root package may use its `allow`; a dependency may use what every package that depends on it grants in its entry, within what those packages may use themselves. Tests and benchmarks are not checked. The check is static: it is not a run-time sandbox.

## Fixes
- Add the capability to `allow` in the root `[capabilities]`, when the root package should use it.
- Grant it to the dependency with `capabilities = ["..."]` in the entry of the package that the message names, and in the root `allow`.
- Remove the use, or move it to a test or a package that is allowed it.
- Run `tsuzuri audit` to see every package's uses, grants and unused capabilities.
