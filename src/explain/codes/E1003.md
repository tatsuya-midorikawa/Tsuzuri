# Type mismatch

## What it covers
An expression has a different type from the one its context requires: an annotation, a parameter or result type, an operator, an index, a fixed-length array literal, an active recognizer's result, or a format spec. The message shows the expected and the found type.

## Fixes
- Change the expression to the expected type, or convert explicitly with `as`; Tsuzuri never converts implicitly.
- When a note points at a `let` annotation, a result type, or a parameter type, correct that declaration if it is the wrong one.
- Pass every argument: a call with too few arguments is a function value, not a result.
- Index with an integer type, and give a fixed-length array literal exactly its declared number of elements.
- Comparisons do not chain: write `a < b && b < c`.
- A local `let` function has one type; use a `def` for a function used at several types.
