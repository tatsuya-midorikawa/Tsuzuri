# Module or package layout error

## What it covers
The files and manifests that make up a program break a naming or layout rule: module filenames and namespaces, the reserved `std` namespace, two files for one module, package names and dependency entries in `Tsuzuri.toml`, one package required from different sources or at incompatible versions, dependency cycles, and symbolic links among the inputs.

## Fixes
- Name each source file after its module: an ASCII identifier that starts with an uppercase letter and matches the directory entry exactly, including case.
- Choose a namespace other than `std`; it is reserved for the standard library.
- Give each module one file; rename a file or change its `namespace` when two collide.
- Use lowercase kebab-case package names, relative dependency paths, and dependency keys equal to the package names.
- Require each package from one source at compatible versions, and break dependency cycles.
- Replace symbolic links with regular files and directories; module discovery does not follow them.
