# Export or extern declaration not supported

## What it covers
A declaration that crosses the C, Objective-C or WebAssembly boundary breaks a rule: an `export def`, `extern def`, `extern view def`, C data symbol or member of an `extern class` uses an unsupported signature, position or target; an extern symbol, class name, selector or WASM import module name is invalid or reserved; declarations of one symbol disagree; or a callback argument is not a plain top-level function.

## Fixes
- Keep the signature to the types that the message lists; wrap other values in a Tsuzuri function.
- Read C data symbols with `unit -> T` on macOS and Linux, and take addresses with `unit -> H` (`extern type copy`).
- Name an extern symbol as a C identifier of at most 255 bytes that does not start with `tz_`, `tsuzuri`, or `__`, and keep its declarations on one kind, import module and C ABI.
- Pass a `@c_layout` record by value only on native targets; declare `ref R` where C takes a pointer.
- Pass an Objective-C object as `ref C`, return it as `C` or `Maybe<C>`, write one colon of a selector for each C argument, and build for an Apple target.
- Pass a callback as the name of a top-level `def` without captures, and call the extern, member or `ObjC` function directly.
