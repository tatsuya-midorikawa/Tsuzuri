# Export or extern declaration not supported

## What it covers
A declaration that crosses the C or WebAssembly boundary breaks a rule: an `export def` or `extern def` signature uses a type the ABI does not support (including `dyn`), an extern symbol or WASM import module name is invalid or reserved, one extern symbol is declared with different signatures, a callback argument is not a plain top-level function, or an active recognizer or extern declaration is exported.

## Fixes
- Keep the signature to the types that the message lists, such as scalars, scalar-only records, borrowed arrays, and string inputs; wrap other values in a Tsuzuri function.
- Name an extern symbol as a C identifier of at most 255 bytes that does not start with `tz_`, `tsuzuri`, or `__`.
- Declare each extern symbol once with one signature, and call it from other modules.
- Pass a callback as the name of a top-level `def` without captures, and call the extern directly with all its arguments.
- Export an ordinary wrapper function instead of an active recognizer or an extern declaration.
