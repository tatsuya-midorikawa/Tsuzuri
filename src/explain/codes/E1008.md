# Export or extern declaration not supported

## What it covers
A declaration that crosses the C or WebAssembly boundary breaks a rule: an `export def`, `extern def`, `extern view def`, or C data symbol uses an unsupported signature or target, an extern symbol or WASM import module name is invalid or reserved, declarations of one symbol disagree on their kind, import module, or lowered C ABI, a callback argument is not a plain top-level function, or an active recognizer or extern declaration is exported.

## Fixes
- Keep the signature to the types that the message lists, such as scalars, scalar-only records, borrowed arrays, and string inputs; wrap other values in a Tsuzuri function.
- Read C data symbols with `unit -> T` (C scalars, `extern type copy`, `Maybe` of one, or view records) on macOS and Linux, and take addresses with `unit -> H` (`extern type copy`).
- Name an extern symbol as a C identifier of at most 255 bytes that does not start with `tz_`, `tsuzuri`, or `__`.
- Keep all declarations of one extern symbol on the same kind, import module, and lowered C ABI classes.
- Pass a callback as the name of a top-level `def` without captures, and call the extern directly with all its arguments.
- Export an ordinary wrapper function instead of an active recognizer or an extern declaration.
