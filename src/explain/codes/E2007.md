# Dependency fetch or verification failure

## What it covers
A dependency could not be fetched or does not match its record: `Tsuzuri.lock` is missing, stale, or malformed, a package is not in the store or its SHA-256 differs from the lockfile or the registry index, `git` is missing or failed, a git dependency contains symbolic links, submodules, or unsafe or case-colliding paths, a registry index lacks a package or version, or `tsuzuri publish` found a commit that differs from the package directory.

## Fixes
- Run `tsuzuri fetch` to download the dependencies and record them in `Tsuzuri.lock`.
- Restore a broken `Tsuzuri.lock` from version control, or delete it and run `tsuzuri fetch`.
- Remove a lockfile entry whose checksum changed only if you trust the new content.
- Install git 2.32 or later, and check the url, the commit id, and network access.
- Set `TSUZURI_CACHE_DIR` to an empty or Tsuzuri cache directory when the package store is unavailable.
- Commit and push the package, then publish that commit.
