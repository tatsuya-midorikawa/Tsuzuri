# Typed hole

## What it covers
The expression `?` or `?name` is a typed hole: a placeholder for an expression that is not written yet. Each hole is one error that reports the type expected at its position (`expected`, or `_` when the position does not decide it), the locals in scope (`scope`, those of the expected type first), and up to ten candidates that produce that type (`candidates`): locals, fields of local records, and functions, constants, builtins and union cases with their arguments filled from the locals where they fit. The checker recovers from a hole, so it causes no other error, and a program with a hole is never built. The name of `?name` only labels the message.

## Fixes
- Replace the hole with an expression of the expected type; a candidate is one.
- When exactly one local has the expected type, the diagnostic offers a `maybe` fix that writes it; `tsuzuri fix --applicability maybe --dry-run` shows it.
- Use `tsuzuri find` to search std and a project by type.
