# Bare `..` slice range across editions

## What it covers
Two notices about a slice written with a bare `..` and an end bound (`ref xs[a..b]` or `ref xs[..b]`):
- `legacy_bare_slice_range`: in editions 2026 and 2027, `..` excludes its end bound (`[a, b)`), whereas from edition 2028 it includes its end bound (`[a, b]`). Reported by default on root-package user sources with a `certain` fix to `..<`.
- `bare_slice_range_meaning_changed`: on a source without a `Tsuzuri.toml` or `--edition`, read with the latest edition (2028 or later), `..` includes its end bound instead of the pre-2028 half-open meaning.

## Fixes
- Write `..<` (`ref xs[a..<b]`) to exclude the end bound in every edition, or `..=` (`ref xs[a..=b]`) to state explicitly that the end bound is included.
- Run `tsuzuri fix` (or `tsuzuri fix --edition 2028`) to rewrite `..` slices in 2026/2027 sources to `..<`, or add `edition = "2028"` in `Tsuzuri.toml` once inclusive bounds are intended.
