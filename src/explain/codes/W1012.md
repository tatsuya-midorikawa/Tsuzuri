# Refutable destructuring pattern in edition 2026

## What it covers
In edition 2026, a single-pattern destructuring binding (a lambda parameter, a `for...in` binding, or a computation `let!`/`and!`/`for` binding) does not cover every value of the bound type, or carries a `when` guard that may fail at runtime. A value that does not match traps with `pattern mismatch`. Edition 2027 rejects the same pattern with `E1021` (`refutable_binding_pattern`).

## Fixes
- For a lambda parameter, use function guards (`\x -> | <pattern> -> ... | _ -> ...`) or bind `x` and `match` inside the body.
- For `for...in` or a computation binding, bind the value to a name and `match` on it in the body.
