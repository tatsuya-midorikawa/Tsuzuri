# Negative integer literal in an index or slice bound

## What it covers
Two warnings when a non-zero negative integer literal (`-1`, `-3`, `-0x10`) is written where Tsuzuri never counts from the end:
- `negative_literal_range_bound`: a negative literal in a slice start/end bound (`ref xs[..-1]`, `ref xs[-1<..2]`) or as the offset of `^` (`ref xs[..^-1]`).
- `negative_literal_index`: a negative literal in a built-in index of an array, fixed-length array, list, `Vec`, `string`, or `utf8string` (`xs[-1]`, `ref xs[-1]`, `xs[-1] = v`), or an integer position component in a window bracket key (`ref t[-1, ..]`, `ref t[Slice.rest(), -1]`), regardless of which `Index` instance takes the window key. Element-mode `Index` class keys (`map[-1]`, `t[-1, 0]`, `t[[-1, 0]]`) are not flagged because each instance defines its own key domain (for example, `HashMap<(i64 * i64), _>` legitimately accepts negative keys).

## Fixes
- In edition 2028, count from the end with `^`: `^0` is the last element (`xs[^0]`, `ref t[^0, ..]`), `^1` is second-to-last (`xs[^1]`), and `ref xs[..^1]` drops the last element.
- In editions 2026 and 2027, compute the position explicitly from `.length` (`xs[xs.length - 1]`), or use `Slice.Sel.Item (Slice.Pos.Back 0)` in a strict `Slice.Sel` window key.
