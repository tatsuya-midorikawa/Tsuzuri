## 目的

「超高速・超省メモリ・超高速ビルド」を判断できるよう、処理時間以外の指標（最大 RSS、確保量、成果物サイズ、起動時間、ビルドの段階別時間、コンパイラのメモリ）を同じ形式で計測・記録する。
他のすべての性能チケットの効果と退行を、この基盤で確認する。

## 現状と計測

- `docs/benchmarks.md` のサマリーは処理時間と相対性能だけで、2026-09-26 の Apple M1 Max の 1 環境です。x86 の実機計測はありません（F05 の注記）。
- 確保回数は一部の節だけにあり、最大 RSS・native の成果物サイズ・起動時間・コンパイラのメモリは記録していません。`benchmarks/run.mjs` は WASM の `wasm.bytes`／`wasm.imports` だけを出します。
- ビルド時間は `benchmarks/run-cache.mjs`（whole-build cache の比較）だけです。段階別の時間を出す仕組みはコンパイラにありません。
- 生データは `target/benchmarks/` のローカル生成物で、Git に追加していません。過去の結果との比較は手作業です。
- `docs/benchmarks.md`「現実的な次の指標」は、コンパイル時間・成果物サイズ・ホスト境界・最大メモリ使用量の継続測定を今後の課題としています。

## 目標と指標

- 全ベンチマークの結果を一つの JSON Lines 形式にそろえる。各行は「種目・実装・仕事量・指標・値・単位・環境」を持つ。
- 指標: 処理時間（CPU 時間と wall time を区別）、最大 RSS、確保回数と確保量、成果物サイズ（native／WASM）、起動から終了までの時間、ビルドの段階別時間、コンパイラの最大 RSS。
- 計測機: Apple Silicon（macOS）、x86_64 Linux（AVX2 と AVX-512 の有無を記録）、AArch64 Linux。

## 施策

### Phase 1: 計測器

- `benchmarks/measure.c`（新規）: 子プロセスを起動し、`wait4` の rusage から最大 RSS と CPU 時間を、単調時計から wall time を返す小さな C の計測器。POSIX で共通に使う。
- コンパイラの段階別時間: 環境変数（例: `TSUZURI_TIME_PASSES=1`）で parse・check・ownership・単相化・closure lowering・IR 生成・外部ツールの各時間を stderr に JSON で出す。成果物は変えない。G17 Phase 0 と同じ仕組みにする。
- 確保の計数: 既存の E2E の確保追跡（`@malloc` を追跡関数へ置換する方式）をベンチマーク用にも使えるようにし、確保回数と確保量を出す。

### Phase 2: 記録と報告

- 結果は日付・計測機・コミット・コンパイラの SHA-256・Clang／rustc などの版とともに JSON Lines で保存する。保存先はリポジトリ外（または専用ブランチ）とし、`docs/benchmarks.md` には要約と保存先を書く。
- `benchmarks/report.mjs` を拡張し、時間・メモリ・サイズの表を同じ規則（Tsuzuri を識別列の次に置き、単位と良い方向を明記）で出す。前回との差も表示するが、合否は判定しない。

## 意味・安全性の保持

- 計測用の出力はオプションで有効にしたときだけ出す。通常のビルド・実行の出力と生成物は変えない。
- 共有 CI では形式と正しさだけを検査し、速度・メモリの閾値を入れない（AGENTS.md）。

## 検証

- 計測器の単体テスト（既知の確保量を持つ C プログラムの RSS・時間の取得、失敗時の終了コード）。
- 段階別時間の出力が全段を含み、合計が wall time を超えないこと。出力の有無で成果物がバイト単位で同一であること。

## 受け入れ条件

- [ ] 既存のベンチマークすべてが共通形式で時間・最大 RSS・サイズを出力する。
- [ ] コンパイラが段階別時間とメモリを出力でき、既定の出力は変わらない。
- [ ] 3 種類の計測機の結果と条件が `docs/benchmarks.md` に記録されている。

## リスク

- macOS の `ru_maxrss` は bytes、Linux は KiB。単位の違いを計測器で吸収する。
- 計測機の負荷・温度・周波数の変動。反復回数と順序の入れ替え、中央値とばらつきの記録で扱う。

## 対象外

- 性能の合否判定の自動化、クラウドの計測サービスの運用。
