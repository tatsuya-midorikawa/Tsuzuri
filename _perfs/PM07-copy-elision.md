## 目的

Copy の配列・リスト・関数値の不要な複製と、所有値の更新でのバッファの作り直しを減らす。
所有権の「最後の使用」の情報を使い、複製の代わりに移動し、バッファをその場で再利用する範囲を広げる。

## 現状と計測

- Copy の配列・リストの複製は新しいバッファの確保と要素の複製を伴います（`FunctionEmitter::clone_value`）。
- 複製の省略は、一回だけ使われるローカル全体を取る場合に限られ、フィールドなどの場所からの取得では複製します（`clones_on_take`、リポジトリの既知の注意点）。
- C01 の消費的な更新（`Array.set` など）は、唯一使用の所有ヒープ配列のバッファを再利用します。
- 文字列の連結 `+` は両辺を消費して新しいバッファを確保し、両辺をコピーします（`tz.string.concat`）。左辺がヒープの所有バッファでも再利用しません。
- A15 で暗黙の複製の警告と明示的な複製 API を計画しています。

## 目標と指標

- 目標: 暗黙の複製の件数（A15 の警告の位置）のうち、最後の使用で移動に置き換えられるものをなくす。文字列を繰り返し連結する処理で、コピー量を C++ の `std::string` の追記と同程度にする。
- 指標: 複製の回数・バイト数、確保回数、時間。

## 施策

- 最後の使用の移動: レコードのフィールド・タプルの要素・union の payload から Copy の値を取り出す場合も、元の値がその後使われなければ複製せずに移動する。部分 move の既存の規則に合わせる。
- 関数への値渡し: 呼び出し後に使わない Copy の配列を渡す場合は移動にする。
- 文字列の連結: 左辺がヒープの所有バッファなら `tz.realloc` で伸ばして右辺だけを書き込む。静的リテラル・スタック上の左辺は従来どおり新しく確保する。
- `Vec` の伸長方針（初回 4、倍増）を計測し、要素サイズに応じた初期容量を検討する。

## 意味・安全性の保持

- Copy の意味（元の値を後で使う場合は独立した値）を変えない。最後の使用かどうかは所有権検査の結果だけで判断する。
- 連結の結果の内容・長さの overflow の検査を保つ。

## 検証

- 複製の回数を確保追跡で検査するテスト（移動になる形と複製が必要な形）。
- 全 E2E を native/WASM × `-O0`/`-O3` で実行し、`live == 0`。
- 文字列の連結を繰り返す種目で、確保・コピー量・時間を記録する。

## 受け入れ条件

- [ ] 最後の使用のフィールド・要素の取り出しが複製にならず、Copy の意味が保たれる。
- [ ] 文字列連結のバッファ再利用で、対象の種目の改善を実測している。

## リスク

- `realloc` がその場で伸ばせない場合は従来と同じコピーになる。償却の保証はないため、効果は計測で判断する（文字列に容量を持たせる変更は PM03 と合わせて検討する）。

## 対象外

- 参照カウントによる共有（C10 Phase 2）、Copy の意味の変更。

## 未決事項

- **文字列の容量**: 既定案は容量を持たせず `realloc` だけを使う。追記の多い処理で不足する場合は `Vec<char>` や将来の builder API を案内する。
