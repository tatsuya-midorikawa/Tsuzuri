## 目的

実行時のプロファイルを使って、分岐の配置・インライン展開・関数の配置を最適化する。
C/C++（Clang の `-fprofile-generate`／`-fprofile-use`）、Rust、Go が持つ PGO を Tsuzuri でも使えるようにし、分岐の多い処理で C/C++ と同じ条件で競えるようにする。

## 現状と計測

- CLI の最適化指定は `-O0`〜`-O3` だけで、PGO の手段はありません（`src/main.rs`）。
- 生成 IR は分岐の確率（`!prof`）を出力していません（2026-09-29 の検索で 0 件）。トラップの分岐は `llvm.trap` へ進む冷たい経路として LLVM が推定します。
- G11 の cache key は最適化の指定を含みます。

## 目標と指標

- 目標: 分岐の多い種目（match の多い処理、文字列の解析、JSON）で、PGO なしの Tsuzuri より速く、同じ PGO を使う C/C++ と同等以上。
- 指標: PGO の有無による時間の差、生成コードの配置の変化。

## 施策

- `build --profile-generate <dir>` で、Clang の IR レベルの計装を有効にした実行ファイルを作る。`build --profile-use <file>` でプロファイルを最適化に使う。
- プロファイルの変換（`llvm-profdata merge`）はツールとして外部の LLVM を使い、`TSUZURI_LLVM_PROFDATA` で指定できるようにする。見つからない場合は明示的なエラーにする。
- プロファイルの内容を G11 の cache key に含める。
- トラップの分岐に既知の確率（ほぼ実行されない）を `!prof` で付け、PGO なしでも配置を改善する。

## 意味・安全性の保持

- PGO は最適化の判断だけを変え、結果・トラップ・評価順序を変えない。プロファイルが古い・一致しない場合も正しい結果を返す（性能だけが変わる）。
- 計装版の実行は通常版と同じ結果を返す。

## 検証

- 計装版・PGO 版で E2E（native × `-O0`/`-O3`）の結果が通常版と同じこと。
- プロファイルの不一致・欠落・破損に対する診断。
- 分岐の多い種目で時間を記録する。

## 受け入れ条件

- [ ] 計装・プロファイルの適用ができ、結果が通常版と一致する。
- [ ] 分岐の多い種目で PGO の効果を実測し、記録している。

## リスク

- プロファイルの形式は LLVM の版で変わる。使える Clang の版を文書化し、版の不一致を診断する。
- WASM では計装の出力先がない。Phase 1 は native だけとする。

## 対象外

- サンプリングによるプロファイル（AutoFDO／BOLT）、実行中の最適化。

## 未決事項
