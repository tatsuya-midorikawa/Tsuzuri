## 目的

小さな計算カーネルだけでなく、確保・文字列・コレクション・再帰データを含む実アプリに近い処理で、C/C++・Rust・Zig・Go と同じ仕事を比較できるようにする。
「超高速・超省メモリ」の主張を、偏りのない種目と一致した条件で判断できるようにする。

## 現状と計測

- 既存の 36 種目は `benchmarks/control`、`computations`、`cpp` の計算カーネル中心で、比較対象は C、C++、Rust、C#、JavaScript です。Zig と Go はありません。
  2026-09-29 の計測機には `go` と `zig` が導入されていません。
- `computations/std_option_owned` は、Tsuzuri が各反復で文字列を 2 回連結（確保）するのに対し、C++／Rust の参照実装は定数の長さ 12 を使い確保しません。確保の条件が一致しておらず、時間比（約 11 倍）は同じ仕事の比較ではありません。
- `control/integer128_mix`（相対性能 0.891）の内側のループは、2026-09-29 に Apple Clang 21 で確認すると Tsuzuri と C の参照実装で命令単位で同一でした。
  2026-09-26 の計測環境の記録は Homebrew Clang 23.1.1 で版が異なります。版の差やコード配置の差が影響した可能性があります。
- 確保の多い処理（木構造、ハッシュ表、文字列処理）とメモリ量の比較がありません。

## 目標と指標

- 10 種目以上の実アプリ型の種目を追加し、各種目で時間・最大 RSS・確保回数・成果物サイズを記録する（PX01 の形式）。
- 全参照実装で、アルゴリズム・データ構造・確保の方針・安全検査・入力・出力の検証をそろえ、そろえられない差を表に明記する。

## 施策

### Phase 1: 既存種目の条件の修正

- `std_option_owned` の C++／Rust の参照実装を、同じ文字列の連結と確保を行う形に直す（`std::string`、`String`）。確保しない版は別の種目名で残す。
- C/C++ と Tsuzuri の IR を同じ Clang の版でコンパイルし、版を記録する。`integer128_mix` を同条件で再計測し、差が残る場合は関数の配置（アラインメント）を固定して比較する。

### Phase 2: 実アプリ型の種目

候補（各種目に C／C++／Rust／Zig／Go の参照実装を用意し、C#／JavaScript は可能な範囲で追加する）:

| 種目 | 主に測る性質 |
| --- | --- |
| binary-trees | 再帰 union の確保と解放、allocator |
| n-body、spectral-norm | 浮動小数点の演算、関数呼び出し |
| fannkuch-redux | 配列の並べ替え、境界検査 |
| fasta、reverse-complement | 文字列・バイト列の生成と変換 |
| k-nucleotide、単語の出現数 | ハッシュ表（C09）と文字列の比較 |
| JSON の解析と出力 | 文字列処理と再帰データ（D08） |
| CSV の集計 | 分割・数値の解析・集計 |
| 整列と二分探索 | `Array.sort` と比較関数 |
| グラフの幅優先探索 | 配列の添字によるグラフ（C10 の Arena） |
| 行列積・画像の畳み込み | 連続配列と SIMD（C11、F08） |

- 機能が未実装の種目（C09、C10、C11、D08 に依存）は、実装されてから追加する。
- 入力は seed から生成し、全実装の出力のチェックサムを照合する。

## 意味・安全性の保持

- 参照実装にも同じ検査（境界検査、整数の折り返し）を課すか、課さない場合はその差を表に書く。Tsuzuri 側の検査を外して比較しない。
- 浮動小数点は fast-math なしで比較する。

## 検証

- 各種目の `--quick` モードで全実装の出力が一致することを CI で確認する（速度の閾値なし）。
- 参照実装のコンパイラの版・最適化の指定を JSON に記録する。

## 受け入れ条件

- [ ] 確保条件の不一致が修正され、`std_option_owned` などの比較が同じ仕事になっている。
- [ ] 実アプリ型の種目で、時間とメモリの結果が記録されている。
- [ ] Zig と Go が比較対象に加わっている。

## リスク

- 言語ごとの慣用的な書き方と、同じアルゴリズムの書き方が異なる。両方を測る場合は種目名で区別する。
- Go の GC の設定（`GOGC`）やスレッド数で結果が大きく変わる。既定値と調整値を分けて記録する。

## 対象外

- 言語の総合的な順位付け、ベンチマークゲームへの投稿。

## 未決事項

- **参照実装の保守**: 既定案は種目ごとに最小の参照実装を置き、依存ライブラリは使わない（標準ライブラリの範囲で書く）。
