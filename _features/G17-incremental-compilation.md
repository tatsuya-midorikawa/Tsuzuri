## 目的

C/C++ の翻訳単位ごとの並列コンパイル、Rust の増分コンパイルと codegen units、C# の Roslyn の増分解析に近いビルド時間とスケーラビリティを目指す。
あわせて、規模に関する固定上限を実測に基づいて見直す。

## 現状

- 毎回、全ソース（std を含む）を parse → check → 単相化 → IR 生成し、一つの LLVM IR モジュールを Clang へ一度渡す（`src/driver.rs`、`src/llvm.rs` の `emit_target`）。並列のコード生成はない。
- G11 は解析と IR 生成の後に照合する whole-build の成果物 cache で、parse／check／IR の cache は対象外。
- LSP も変更ごとに全体を再検査する（G07）。
- 上限: ソース 1 MiB／ファイル（`MAX_SOURCE_BYTES`、`E0003`）、特殊化はプログラム全体で 1,024（`src/polymorph.rs` の `MAX_SPECIALIZATIONS`、`E1017`）、
  既知呼び出しの worker 特殊化 1,024（`src/call_specialization.rs`）、ソース 4096／ディレクトリ 1024（E03）、package 1024（E04）、値 64 KiB（`MAX_VALUE_BYTES`）、深さ 128。

## 仕様

### Phase 0: 計測（実装対象）

- 段階ごとの時間とメモリを出力する内部オプション（例: `TSUZURI_TIME_PASSES=1`、stderr に JSON）を追加する。出力の成果物は変えない。
- `benchmarks/run-cache.mjs` を拡張し、1,000／5,000 モジュールと、ジェネリック関数を多用する合成プロジェクトで計測して `docs/benchmarks.md` に記録する。

### Phase 1: 並列コード生成（実装対象）

- 単相化後の関数集合を決定的な規則（関数 ID の安定順による分割）で N 個の IR モジュールに分け、Clang を並列に起動してからリンクする。N は CPU 数によらず関数数から決め、出力を機械によらず決定的にする。
- 分割で inline の境界が変わり得るため、`-O3` は ThinLTO を使うか一つのモジュールのままにするかを実測で決める（未決事項）。意味は変わらない。

### Phase 2: モジュール単位の解析キャッシュ（設計方針）

- parse 結果と公開シグネチャのハッシュをモジュールごとに保存し、依存先のシグネチャが変わらなければ本体の再検査を省く。ジェネリック本体と単相化の依存関係を追跡する。
- LSP（G12）も同じキャッシュを使う。

### Phase 3: 上限の見直し（設計方針）

- Phase 0 の計測に基づき、特殊化上限を「全体の上限」と「型が成長する多相再帰の検出」の二段にする、ソース上限を引き上げるなどを判断する。上限と `E1017` は維持する。

## 設計

- IR の分割は `emit_target` の出力を関数単位で振り分ける形にし、型定義・intrinsic 宣言・ランタイムは各モジュールに決定的に複製するか一つにまとめる。
- driver の Clang 起動は既存のステージングと出力保護を維持し、並列の一時ファイルを専用の一時ディレクトリに置く。
- G11 の cache key は分割の設定を含める。

## 実装手順

1. **計測**: 段階時間と合成プロジェクト。確認: 計測結果の記録。
2. **IR 分割**: 確認: 分割前後で全 E2E（native/WASM × `-O0`/`-O3`）の結果一致、IR の決定性。
3. **並列 Clang**: 確認: ビルド時間の計測、失敗時の出力保護。
4. **Phase 2／3 の設計レビュー**: 計測結果を添えて判断する。

## テスト計画

- 分割あり・なしで同じ実行結果、トラップ位置（G04）、DWARF（G08）が一致すること。
- 並列起動の一部が失敗した場合に既存の出力を変更しないこと。

## 落とし穴

- WASM は wasm-ld で複数 object を結合する必要があり、threads の relocatable 結合（F06）と手順を揃える。
- 分割でランタイムの weak シンボルの重複や、macOS の `-keep_private_externs` の既存の注意点に再び当たる。

## 対象外

- 分散ビルド、コンパイラ自体の並列な型検査（Phase 2 の設計で検討）。

## 未決事項

- **`-O3` の分割**: 既定案は ThinLTO と単一モジュールを実測で比較して決める。
- **上限の新しい値**: 既定案は Phase 0 の計測後に人間が判断する。
