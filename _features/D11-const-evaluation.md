## 目的

lookup table・CRC 表・係数表などを、実行時の初期化コストなしに関数で生成できるようにする。
C++ の `constexpr`／`consteval`、Rust の `const fn` と同じ用途を、実行時と同じ数値・トラップの意味で提供する。

## 現状

- D06 の `const` は具体型の値。整数・binary 浮動小数点の演算、`if`、cast、比較、配列・タプル・レコードのリテラルを評価する（`src/constants.rs`）。
- 関数呼び出し・ループ・`match`・ラムダ・借用・代入・`new` は `E1026` で拒否し、decimal 演算も拒否する。
- 上限: 依存の深さ 128、探索 1024 件、評価・展開 1,048,576 ノード。依存評価は明示スタックで行う。
- 定数は利用ごとに通常の所有値を生成し、static lifetime を導入しない（D-28）。

## 仕様

### Phase 1（実装対象）

- `const def` 修飾の関数を const 式から呼べる。本体は既存の型付き IR で、次を許可する: `let`、`let mut` と代入、`if`、`match`、`for`／`while`、
  `new [T](n, f)`、配列・レコード・union、純粋な `const def` の呼び出し（相互再帰は深さ上限内）。
- 禁止: `extern`、IO、Task、Parallel、Debug、Gpu、借用を返す関数、関数値の保存（呼び出し先は静的に決まる必要がある）。違反は `E1026`。
- 意味は実行時と同じ: 整数の折り返し、binary 浮動小数点の丸め（APFloat）、トラップ（`E1026` として報告し、位置を示す）。
- 上限: 評価ステップ 16,777,216、確保合計 64 MiB、呼び出しの深さ 128。超過は `E1026`。
- `const def` は通常の関数としても実行時に呼べる。

### Phase 2（設計方針、要承認）

- 大きな定数配列を読み取り専用の静的データとして一度だけ出力し、`ref` だけで参照できるようにする（static region の導入が必要。D-28 の「static lifetime を導入しない」の変更）。

## 設計

- `constants.rs` の評価器を、型付き IR を直接解釈する有界インタプリタへ拡張する。値の表現は既存の定数リテラル展開と共有する。
- 評価の結果は従来どおり型付きリテラルへ展開する。
- f16/f128/decimal は Rust 側で同一の実装を持たないため Phase 1 でも拒否を維持する。

## 実装手順

1. **`const def` の宣言と検査**: 禁止事項の静的検査。確認: `tests/constants.rs` の拒否ケース。
2. **インタプリタ**: 制御構文と呼び出し。確認: 実行時に同じ関数を呼んだ結果と一致（native/WASM × `-O0`/`-O3`）。
3. **上限とトラップ**: ステップ・確保・深さ、トラップ位置。確認: 各上限の境界テスト。
4. **表の生成例**: CRC32 表の生成と利用。確認: 生成 IR の決定性。

## テスト計画

- 同じ `const def` をコンパイル時と実行時に評価し、全数値型で結果を照合する差分テスト。
- 資源上限でコンパイラがスタック枯渇しないこと（2 MiB のテストスタック）。

## ドキュメント

- `docs/language.md` コンパイル時定数、`_docs/language-reference/values-and-constants.md`。

## 受け入れ条件

- [ ] `const def` をコンパイル時に評価でき、結果が実行時と一致する。
- [ ] 上限とトラップが `E1026` で報告され、コンパイラが停止・枯渇しない。

## 落とし穴

- インタプリタを再帰で実装するとコンパイラのスタックを使い切る。D06 と同じく明示スタックにする。
- APFloat と LLVM の定数畳み込みで NaN の扱いが異なる場合がある。既存の canonical 規則に揃える。

## 対象外

- 型レベルの計算、マクロ、コンパイル時の IO。

## 未決事項

- **static データ**: 既定案は Phase 2 で人間が判断する。
- **修飾子の表記**: 既定案は `const def`（既存の予約語の組み合わせで新しい予約語を増やさない）。
