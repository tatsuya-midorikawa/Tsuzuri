## 目的

長さを型に含む値型の配列（C/C++ の `T[N]`・`std::array`、Rust の `[T; N]`、C# の inline array）を追加する。
座標・小行列・lookup table・SIMD 前後の作業領域を、ヒープ確保なしのビット複製に近いコストで扱えるようにする。

## 現状

- 配列型は `[T]` だけで、長さは型の一部ではない。旧 `[T; N]` 形式は `src/parser.rs` が
  `"array types use '[T]', without a length; use 'new [T](length, initializer)' to create an array"` で拒否する。
- `[T]` は `{ ptr, i64 }` の記述子。束縛リテラルの要素はスタック、それ以外はヒープに置く。Copy 配列の複製は新しいバッファの確保を伴う。
- SIMD 型（`src/simd.rs`）は 128-bit 固定の値型で、任意長の固定配列の代わりにはならない。
- 型パラメーターは型だけ（`'a`）。値を型引数に取る仕組みはない。D06 の `const` は具体型の値だけ。

## 仕様

### Phase 1: リテラル長の固定長配列（実装対象、構文は要承認）

- 型 `[T; N]`。`N` は非負の `i64` 整数リテラルまたは `i64` の `const` 名。旧構文の再導入になるため、着手前に人間の承認を得る。
- 値型として要素を inline に保持する。`layout_size` は `N` 個分で、`MAX_VALUE_BYTES`（64 KiB）を超えればレイアウトの診断。
- リテラル: 期待型が `[T; N]` の位置の `[a, b, c]` は要素数を照合し、不一致は `E1003`。要素は左から右に一度ずつ評価する。
- 生成: `FixedArray.init :: (i64 -> 'a) -> ['a; N]`（`N` は期待型から決定し、添字昇順に呼ぶ）。
- 索引 `values[i]` は `i64`。範囲外は従来どおり実行時トラップ（定数添字でも意味を変えない）。
- 呼び出し引数の暗黙の借用表に `ref [T; N]` → `ref [T]`（スライス）を追加する。逆方向の変換はない。
- 全要素が Copy なら Copy で、複製は確保なしのコピー。非 Copy 要素なら move と要素ごとの drop。
- 公開 ABI: Phase 1 では export 不可。Phase 2 でスカラー要素の固定長配列をレコードのフィールドとして許可する（E12 と調整）。

### Phase 2: const ジェネリクス（設計方針）

- 型パラメーターとして長さを受け取る（例: `record Grid<'a, const N: i64> { cells: ['a; N] }`、関数の `[f64; N] -> [f64; N] -> f64`）。
- 長さの算術（`N * M`）は Phase 2 の対象外。具体化ごとに別の特殊化になり、上限 1,024 に数える。

## 設計

- `Type::FixedArray(Box<Type>, u64)` を追加し、GUIDE §6.3 の全項目を更新する。`Type::Array` とは別の型で、暗黙の相互変換はしない。
- LLVM 表現は `[N x T]`。フレームの確保・relocate・clone・drop は既存のレコード（値型）の経路を再利用する。
- 所有権は要素単位ではなく値単位。要素の取り出し move は配列と同じく拒否する。

## 実装手順

1. **構文と型**: `[T; N]` の解析、`Type::FixedArray`、表示とレイアウト。確認: 旧拒否テストを新仕様へ更新し、`N` の不正を拒否。
2. **リテラルと init**: 要素数の照合、評価順序。確認: `tests/arrays.rs` の受理・拒否。
3. **索引・借用・スライス化**: 境界検査、`ref [T; N]` からの借用。確認: E2E でトラップ位置（G04）。
4. **Copy・drop**: 値型の複製と非 Copy 要素の drop。確認: 確保追跡でヒープ確保 0 回と `live == 0`。
5. **Phase 2 の設計レビュー**: const ジェネリクスの構文を承認する。

## テスト計画

- Rust: 受理・拒否（要素数、`N` の型、負の `N`、上限）、レコードのフィールド・タプル・union payload。
- E2E: native/WASM × `-O0`/`-O3`、境界トラップ、確保回数の検査。
- 性能: `[f64; 3]` の座標計算を `[f64]` 版・C の `double[3]` と比較し、生成コードを確認して記録する。

## 受け入れ条件

- [ ] 固定長配列を値型として宣言・生成・索引・借用でき、Copy の複製でヒープ確保が起きない。
- [ ] 既存の `[T]` の意味・IR が変わらない。
- [ ] 構文の再導入について承認が記録されている。

## 落とし穴

- `MAX_VALUE_BYTES` を超える大きな固定長配列をスタックへ置くとスタック枯渇を招く。上限検査を具体化後にも行う。
- 暗黙の借用をスライスへ広げると、既存のオーバーロードのない関数解決で曖昧さが出ないか確認する。
- WASM の 1 MiB スタックと大きな値型の組み合わせ。

## 対象外

- 長さの算術、可変長の inline 配列、固定長配列の直接の要素代入（C08 の方針に従う）。

## 未決事項

- **構文**: 既定案は `[T; N]` の再導入。代替案は `Array<T, N>` のような型適用。
- **const ジェネリクスの宣言形式**: 既定案は `const N: i64` を型パラメーター列に置く形式。
