## 目的

F# Interactive（`dotnet fsi`）や C# の対話環境のように、宣言と式を一つずつ入力して結果と型を確認できる環境を用意する。
単一ファイルのスクリプトを `Main.tz` のプロジェクト構成なしで実行できるようにする。

## 現状

- CLI は `check`／`build`／`run`／`test`／`fmt`／`doc`／`lsp`。対話モード・標準入力からの評価・単一ファイルのスクリプト実行はない。
- `run` はプロジェクト（`Main.tz`）単位で、毎回 Clang を起動する。G11 の whole-build cache は解析と IR 生成の後で成果物を照合する。
- 値は所有権で管理され、実行中のプロセスの状態を保持して再利用する仕組みはない。

## 仕様

### Phase 1: 再コンパイル型の REPL（実装対象）

- `tsuzuri repl [--target native|wasm32] [-O0..3]`。入力を宣言（`def`／`record`／`union`／`type`／`const`／`class`／`instance`／`let` 束縛）と式に分類する。
- セッションは宣言の列として保持し、各入力で一時プロジェクトを生成して `run` と同じ経路で実行する。式は Display で結果と型を表示する。
- `let` 束縛は宣言として保持し、後続の入力のたびに再計算する。IO を伴う束縛は再実行を避けるため拒否し、式としてだけ実行できる（理由を表示）。
- 同じ名前の再宣言は置き換えとし、依存する後続の宣言を再検査する。エラーの入力はセッションに追加しない。
- コマンド: `:type expr`、`:load file`、`:list`、`:reset`、`:quit`。
- 一時プロジェクトは専用の一時ディレクトリに作り、出力保護（既存ファイルの上書き禁止）を維持する。

### Phase 2: スクリプト（設計方針）

- `tsuzuri script file.tz [args...]`: 任意の名前の単一ファイルを入口として実行する。先頭の shebang 行（`#!/usr/bin/env tsuzuri script`）を無視する。

### Phase 3（研究）

- LLVM の JIT による再コンパイルなしの評価。LLVM の C API に結合しない現在の方針（docs/architecture.md）と衝突するため、人間が判断する。

## 設計

- REPL は driver のプロジェクト読み込みにメモリ上のソース一覧を渡す形で実装し、ファイルシステムへの書き出しは Clang に渡す成果物だけにする。
- 入力の分類はパーサーのトップレベル解析を使い、独自の簡易パーサーを作らない。
- 再コンパイルの時間を G11 の cache と G17 の解析キャッシュで短縮する。

## 実装手順

1. **入力の分類とセッション**: 確認: `tests/repl.mjs`（標準入力を流し込む非対話テスト）。
2. **式の評価と型表示**: 確認: native/WASM で同じ出力。
3. **再宣言と依存の再検査**: 確認: 置き換え後に依存する宣言のエラー報告。
4. **IO 束縛の拒否とコマンド**。
5. **Phase 2 のスクリプト実行**。

## テスト計画

- 非対話の E2E（入力列 → 期待出力）を native/WASM で実行する。エラー入力の後もセッションが壊れないことを確認する。
- 応答時間を計測して記録する（閾値なし）。

## 落とし穴

- 再計算により副作用のある `extern`・Debug 出力が繰り返される。束縛の再計算で出力が重複することを表示で明示するか、束縛に使える式を制限する。
- 長いセッションで再コンパイル時間が増える。セッションの大きさを表示する。

## 対象外

- Notebook の統合（VS Code notebook は別途）、実行中のプロセスの状態保持。
