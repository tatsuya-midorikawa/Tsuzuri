## 目的

`///` で API の説明を宣言に添付し、`tsuzuri doc` で決定的な Markdown API 文書を生成する。E01 の `private` に従い、公開 API だけを出力することで、標準ライブラリとユーザープロジェクトの参照資料を自動生成できるようにする。

## 現状

- `src/lexer.rs` の `Lexer::tokens` は `//` 行コメントを改行まで読み飛ばし、`/* ... */` は `Lexer::comment` で入れ子対応して捨てる。コメント token は存在しない。
- `src/syntax.rs` の `Program`, `RecordDecl`, `FunctionDecl`, `SignatureDecl`, `ClassDecl`, `InstanceDecl` に docs / visibility field はない。
- `src/parser.rs` の `Parser::program` は top-level `record`, `class`, `instance`, `def`/`fn`/`let` を直接分岐し、コメントを扱わない。
- `src/check.rs` の `Type::display` は解決済み型を表示できるが、宣言時の制約や docs text は保持しない。
- `src/main.rs` に `doc` サブコマンドはない。
- E01 未実装のため、現状はすべての通常宣言がモジュール間で公開扱いである。

## 仕様

### doc comment syntax

```text
/// One-line summary.
/// More details.
def answer :: i64
fn answer = 42
```

- `///` は doc comment。行末までを text とし、先頭の `///` の直後に 1 個の空白があれば取り除く。
- 連続する `///` は `\n` で結合する。
- `//` と `/* ... */` は従来どおり通常コメントで docs にならない。
- Phase 1 は `///` のみ。`/** ... */` は対象外。
- doc comment は直後の宣言に添付する。

添付対象:

- `def`（関数の API docs。対応する `fn` / `let` 実装側の doc comment はエラー）
- `record`
- `class`
- class methods の `def`
- E01 後の `private def` / `private record` 等は docs を持てるが、通常の `tsuzuri doc` には出力しない
- D06 後の `const`
- A02/A05 後の `union` / `type`

添付しないもの:

- `fn` 実装単体
- `instance` と instance method（API docs は class method 側に書く）
- `let` ローカル、top-level entry code、computation expression statements

misplaced doc comment は warning ではなく `E0002` error にする。

理由: 現状は warning infrastructure がなく、D-16 に doc comment 用 warning code もない。コメントを黙って捨てると API docs の欠落に気づけないため、構文エラーとして止める。

### CLI

```text
tsuzuri doc source.tz|source.tt|source.tc|directory -o outdir [--json]
```

- 入力の読み方は `check` と同じ。project 全体を parse / check してから docs を出す。
- `-o` / `--output` は必須。既定出力先は作らない。
- `--json` はエラー診断の出力形式だけに効く。生成 docs は Markdown。
- `--target`, `--emit`, `-O*`, `--cpu`, `-g` は `doc` では `E2000`。

### 出力

出力 directory:

```text
outdir/
  index.md
  Main.md
  Point.md
  ...
```

- module file name sort で deterministic に生成。
- `index.md` は module 一覧。
- 各 `<Module>.md` は公開（non-private）宣言を source order で列挙する。
- private 宣言は出力しない。private class method という概念が E01 にない場合、class が public なら method も出す。
- docs text は Markdown としてそのまま出力する。ただし HTML sanitization はしない。生成先は local docs であり、ホスト側の renderer の責務。

関数 format:

````markdown
## `answer`

```tsuzuri
def answer :: i64
```

One-line summary.
````

制約付き:

```text
def twice :: (Add 'a, Copy 'a) => 'a -> 'a
```

record:

```text
record Point {
  x: f64
  y: f64
}
```

class:

```text
class Score 'a {
  def score :: &'a -> i32
}
```

### output protection

- `outdir` が存在しない場合は作成する。
- `outdir` が存在する場合、以下を満たすときだけ上書きする:
  - directory である。
  - `.tsuzuri-docs` marker file がある。
  - marker に `generated by tsuzuri doc` を含む。
- 既存の任意 directory を marker なしに消したり上書きしたりしない。違反は `E2003`。
- 出力は temporary directory に全ファイルを書き、成功後に publish する。file 単位で途中生成を残さない。

## 設計

### 追加する AST

`src/syntax.rs`:

```rust
#[derive(Clone, Debug)]
pub struct Documentation {
    pub text: String,
    pub span: Span,
}

pub struct RecordDecl {
    pub doc: Option<Documentation>,
    pub name: Ident,
    pub fields: Vec<Parameter>,
}

pub struct FunctionDecl {
    pub doc: Option<Documentation>,
    // existing fields...
}

pub struct SignatureDecl {
    pub doc: Option<Documentation>,
    // existing fields...
}

pub struct ClassDecl {
    pub doc: Option<Documentation>,
    pub methods: Vec<SignatureDecl>,
    // existing fields...
}
```

E01 後の visibility field と同じ struct に置く。A02/A05/D06 後は `UnionDecl`, `TypeAliasDecl`, `ConstDecl` に同じ `doc` field を追加する。

### lexer

`TokenKind::DocComment(String)` を追加する。

`Lexer::tokens` の line comment 分岐:

- `self.rest().starts_with("///")` なら `DocComment` token を push。
- `////` は `///` docs text が `/...` で始まるものとして扱う。通常コメントにしない。
- `//` は従来どおり捨てる。

block comment は docs ではないため `Lexer::comment` は変更しない。

### parser

`Parser` に pending docs を持たせる。

```rust
fn take_doc(&mut self) -> Result<Option<Documentation>, Diagnostic>;
fn reject_doc(&mut self) -> Result<(), Diagnostic>;
```

- top-level loop の先頭で `DocComment` を 1 個以上読む。
- 次 token が docs 添付対象なら `doc` として渡す。
- 添付対象でなければ `E0002`。
- `def` signature と `fn` implementation が分かれている関数では、docs は `def` にだけ許可する。
- `fn` の前に doc がある場合は `"doc comments attach to 'def', not to the implementation"` で `E0002`。
- class body の method `def` でも同じ処理をする。

### doc generator

`src/docgen.rs` を追加する。

```rust
pub struct DocOptions<'a> {
    pub output: &'a Path,
    pub include_private: bool,
}

pub fn generate(project: &Project, options: DocOptions<'_>) -> Result<Vec<String>, Diagnostic>;
```

- `include_private` は Phase 1 CLI では false 固定。将来 internal docs 用に残す。
- `generate` は `Project` の source を parse し、`project.analyze()` で型・可視性エラーがないことを確認してから出力する。
- signature rendering は AST から行う。`TypeExpr` / `ConstraintExpr` をそのまま deterministic に pretty print し、宣言者が書いた API 形（制約、型変数）を保つ。
- `Type::display` は check 後の補助表示や hover には使えるが、docs の primary signature は AST を使う。

### コンパイラ段階ごとの変更

| 段階 | 変更 |
|---|---|
| lexer | `DocComment` token を保持 |
| parser | docs を宣言 AST に添付し、misplaced docs を `E0002` |
| check | docs は型検査に影響しない。E01 visibility と組み合わせて docgen が public 判定 |
| polymorph / control / closures / ownership / llvm / runtime | 変更なし |
| driver | docs 用 output protection helper を追加。既存 build の output protection は変更しない |
| main | `Action::Doc` と `-o` 必須処理 |

### 前提とする他チケットのインターフェース

E01 が宣言 AST に visibility を追加している前提:

```rust
pub enum Visibility { Public, Private }
```

名前や配置が異なる場合、G09 は docgen 側で E01 の public/private 判定 API に合わせる。private を無視して docs に出す実装は不可。

### 他チケットへの提供インターフェース

- G07 は `Documentation` を hover markdown に差し込める。
- G06 は `docgen` の fenced `tsuzuri` code block 抽出 helper を再利用できる。
- E02 は std source の docs を `docs/std/` へ生成する command を CI に追加できる。

## 実装手順

1. **AST と lexer**
   - `TokenKind::DocComment` と `Documentation` を追加。
   - `Lexer::tokens` で `///` を token 化。
   - 確認: lexer unit test で `/// hello` が token、`// hello` は捨てる。
2. **parser 添付**
   - `Parser::program` と class method loop で pending docs を読む。
   - `def` / `record` / `class` に `doc` を設定。
   - misplaced docs を `E0002`。
   - 確認: `tests/docs.rs` で accepted / rejected を診断 code 付きで検査。
3. **docgen rendering**
   - `src/docgen.rs` を追加し、AST signature pretty printer を実装。
   - Markdown escaping は heading / code fence の構造だけ制御し、docs text はそのまま。
   - 確認: golden Markdown を byte-for-byte 比較。
4. **CLI**
   - `Action::Doc`、`tsuzuri doc ... -o outdir` を追加。
   - build-only options を拒否。
   - 確認: `parse_arguments` tests。
5. **output protection**
   - marker file 方式で既存 directory の誤上書きを防ぐ。
   - 確認: marker なし directory で `E2003`、marker ありで更新。
6. **std docs later hook**
   - E02 後に `std/` を入力できることを docs に書く。G09 実装時点で std がなければ hook のみ。
7. **docs 更新**
   - `docs/language.md` に doc comment 構文。
   - `README.md` に `tsuzuri doc`。

## テスト計画

- Rust (`tests/docs.rs`):
  - `///` が `def`, `record`, `class`, class method に添付される。
  - `fn` 実装前、entry code 前、file 終端の doc comment は `E0002`。
  - 通常コメントは AST に残らない。
  - docs が型検査結果を変えない。
  - private 宣言（E01 後）が docgen に出ない。
- Node (`tests/docgen.mjs`):
  - fixture project から `tsuzuri doc -o outdir`。
  - `index.md` と module Markdown を golden と比較。
  - 2 回実行して byte-identical。
  - marker なし existing dir を `E2003` で拒否。
- docs-only generation は codegen しないため native/WASM E2E は不要。ただし parser/check を触るため `cargo test --locked` は必須。

## 落とし穴

- doc comment を lexer で捨てると parser で添付できない。
- `def` と `fn` が離れていても docs は `def` 側にだけ属する。
- docs text を型検査や名前解決に影響させてはいけない。
- private の判定は E01 の仕様に従う。`export` はホスト ABI であって docs public 判定ではない。
- 出力 directory を `rm -rf` で消す実装は不可。marker と temporary publish を使う。
