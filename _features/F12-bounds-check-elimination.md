## 目的

配列の境界検査のコストを、トラップの有無・位置・順序を変えずに減らす。
まず現状の除去状況を計測して退行を検出できるようにし、LLVM が除去できない形に絞ってコンパイラ側の対策を追加する。

## 現状

- 添字アクセスは境界検査（`TrapKind::BoundsCheck`）と `llvm.trap` への分岐を生成する。範囲解析・ループの版分けはコンパイラにない。
- 2026-09-29 の確認（arm64 macOS、`--emit object -O3`）:
  - `for value in values` は反復条件だけで、要素ごとの追加の検査を生成しない。
  - `for i in 0i64 .. (values.length - 1) do total = total + values[i]` は `-O0` の IR に要素ごとの検査があるが、`-O3` では LLVM が除去してベクトル化した。
  - 残る検査は公開 ABI の入口（長さ・null・alignment）だけだった。
- 入れ子の配列（`[[T]]`）、別の配列から読んだ添字、非アフィンな添字、途中脱出のあるループでの除去は未計測。
- 除去は LLVM の最適化に依存し、保証・退行検査はない。

## 仕様

- 意味は変えない: トラップする入力では、同じ位置で、先行する副作用（extern、Debug、確保）の後にトラップする。検査を副作用より前へ移動しない。
- Phase 0（計測、実装対象）: 代表的なループ形（単純な添字、入れ子配列、ストライド、逆順、`Array.*` の bulk API、スライス）について、`-O3` の生成コードに残る検査の数を記録する IR／アセンブリ検査スクリプトを追加する。
  結果を `docs/benchmarks.md` に記録し、C（検査なし）と Rust（検査あり）の同じ形と比較する。
- Phase 1（実装対象）: 意味を保つ事実を IR に付ける。
  - 配列・スライスの記述子の長さは常に `0 ≤ length ≤ i64::MAX`。長さの読み出しに `!range` などの事実を付け、LLVM の除去を助ける。
  - コンパイラが構造的に範囲内と証明できるアクセス（ループの反復変数が `0..length-1` の範囲を動き、対象の配列がループ内で置換されない）では検査を生成しない。
- Phase 2（設計方針）: ループの版分け。アフィンな添字のループで、全反復の範囲を入口で一度だけ検査し、成功したら検査なしの版、失敗したら元の検査付きの版を実行する。
  失敗時は元の版がそのまま実行されるため、トラップの位置と先行する副作用は変わらない。

## 設計

- 証明は所有権検査の結果（ループ内で配列の束縛が置換・move されないこと）と型付き IR の範囲ループ（`range_loop`）の形だけを使う。未知の関数呼び出しで配列が変わらないことは、共有借用の不変性から保証される。
- 検査を省く場合も `TrapSite` の表（G04）は変えない（省いた位置はトラップしないことが証明されている）。
- 生成 IR の決定性を保つ。

## 実装手順

1. **計測スクリプト**: `benchmarks/` に検査数と時間を記録するスクリプト。確認: `--quick` で動作し、合否閾値を持たない。
2. **長さの事実**: `!range` の付与。確認: 既存 E2E（`tests/primitives.mjs` など）が native/WASM × `-O0`/`-O3` で不変、計測で検査数が増えない。
3. **構造的な証明**: 範囲ループでの省略。確認: トラップ位置テスト（`tests/trap_locations.rs`）、ループ内で配列を置換するケースで検査が残る。
4. **Phase 2 の設計レビュー**: 版分けの対象形とコードサイズの影響。

## テスト計画

- トラップする入力の位置・順序が変わらないことを、副作用（extern のカウンター）を含むケースで検査する。
- 検査を省く形と省かない形の両方で native/WASM × `-O0`/`-O3` の結果を照合する。

## 受け入れ条件

- [ ] 代表的なループ形の検査数が記録され、退行を検出できる。
- [ ] 省略した検査がトラップしないことが証明済みの位置に限られ、トラップの位置・順序が変わらない。

## 落とし穴

- `nsw`／`nuw` を根拠なく付けると、折り返しの意味を変える。付与は証明できる場合だけにする。
- `llvm.assume` の乱用は最適化を妨げることがある。効果を計測してから使う。

## 対象外

- 利用者が検査を無効にするオプションや unchecked API（安全性を下げる選択肢は提供しない）。

## 未決事項
