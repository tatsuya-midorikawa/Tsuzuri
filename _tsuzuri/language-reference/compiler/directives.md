# コンパイラ ディレクティブ

Tsuzuri 0.1.0 には、`#if`、`#nowarn`、`#define` のようなコンパイラディレクティブも、C のプリプロセッサもありません。`src/lexer.rs` と `src/parser.rs` は `#` を指令として扱いません。行頭の `#if` は、式を期待する位置の構文エラー `E0002` です。

```text
./hash.tz:1:1: error[E0002]: expected an expression
  1 | #if true
    | ^
```

条件コンパイルでソースの意味が変わることを避け、同じファイルから同じ診断と同じ成果物が出るようにするためです。暗黙のマクロが存在しないため、読んだテキストとコンパイラが見るテキストに齟齬が生じません。

代わりに、ソース上の属性、`Tsuzuri.toml`、コマンドライン、警告を失敗にするフラグを使い分けます。どれも、指令のようにトークン列を書き換えるものではありません。

## この記事のポイント

- `#` で始まる指令は無く、`#if true` はそのまま `E0002` です。
- 関数の版や検査付き算術は、属性 `@cpu`、`@checked`、`@literal` で書きます。
- プロジェクトの既定は `Tsuzuri.toml` の 4 セクションだけです。
- ターゲットや最適化は、コマンドラインで明示します。
- 警告をエラー相当にする公式の方法は `--deny-warnings` です。

## プリプロセッサを置かない理由

プリプロセッサは、コンパイル前に別のプログラムを作ります。含まれるファイルや定義の順番で、同じ行の意味が変わります。Tsuzuri は、字句解析の結果がソースのテキストと対応し、生成 IR がオプションとソースから決まることを優先しています。

プラットフォームの差は、指令でソースを分岐させるのではなく、次のどれかで表します。

- ターゲットそのものを `--target` で選ぶ。
- そのターゲットで使えない API は、コンパイルエラーにする。既定の wasm32 が OS API を拒否するのがその例です。
- 実行時に CPU が選ぶ版は、`@cpu` で関数ごとに宣言する。

「この行だけ Windows では別の式にする」といったソースコードレベルでの分岐機能は、Tsuzuri 0.1.0 には存在しません。

## ソース上の属性

属性は、続く宣言や文の意味を足す印です。トークンを消したり、別ファイルを挿入したりはしません。詳しい構文は [属性](../values-and-functions/attributes.md) と [言語仕様](../../../docs/language.md#コンパイル時定数) にあります。ここでは、指令の代わりになる 3 つだけを見ます。

### `@literal`

`@literal def 名前 :: 型 = 式` は、コンパイル時定数です。本体を持たない指令ではなく、普通の宣言です。値として使うので、`()` で呼びません。

```tsuzuri run=42
@literal def Answer :: i64 = 40 + 2

Answer
```

実行結果:

```text
42
```

同じものは `const Answer: i64 = 42` とも書けます。`@literal` は、その互換の形です。定数式から `extern` を呼ぶことはできません。ゼロ除算や循環は `E1026` です。

### `@checked`

`@checked` は、続く文が評価する整数の `+`、`-`、`*`、`**`、単項の `-` を検査します。オーバーフローが発生した場合は折り返さず、`OverflowException` を送出します。`@checked` を付けない通常の算術演算は、その型のビット幅でモジュロ折り返し（ラップアラウンド）します。

```tsuzuri run=42
def add :: i64 -> i64 -> i64 = \left right ->
    @checked left + right

add 20 22
```

実行結果:

```text
42
```

`let`、`let!`、`do!`、`return`、式文に付けます。ブロック全体へ 1 つ書いて中の全部を覆う、という指令ではありません。中の文にそれぞれ付けます。

### `@cpu`

`@cpu ["avx2"]` のように、トップレベル関数の `def` の直前へ命令セット名を並べます。native の実行ファイルとオブジェクトは、その関数を命令セットごとにもう一度コンパイルし、実行時に CPU が対応する最新の版を選びます。名前は `sse4.2`、`avx2`、`avx512`、`sve`、`sve2` です。ビルド先で選べない名前は無視され、未知の名前、重複、空の並びは `E0002` です。

```tsuzuri run=42
@cpu ["avx2"]
def total :: i64 -> i64 -> i64 = \left right ->
    left + right

total 20 22
```

実行結果:

```text
42
```

実行環境の CPU が AVX2 に対応していなくても、ポータブルな既定版が残るため同一の計算結果が得られます。整数の折り返し、浮動小数点の演算順序、NaN の扱い、トラップの挙動はバージョン間で一切変わりません。WASM、`--emit llvm`、`--freestanding` ではポータブル版のみが生成されます。

テストで版を固定する実行時の変数が `TSUZURI_CPU_FORCE` です。コンパイラ指令ではなく、生成コードが読みます。値と失敗時のメッセージは [コンパイラ オプション](option.md) に書いてあります。

## Tsuzuri.toml の設定

プロジェクトルートの `Tsuzuri.toml` が、パッケージの既定です。パーサーが受け付けるセクションは 4 つだけで、`[package]` のあとに、任意の `[dependencies]`、`[wasm]`、`[native]` がそれぞれ高々 1 回です。知らないキーや、セクションの重複は `E0002` です。`#` はコメントで、指令ではありません。

```toml
[package]
name = "shop"
version = "0.1.0"
namespace = "Acme::Shop"

[dependencies]
pricing = { path = "../pricing" }

[wasm]
max-memory = "64MiB"
stack-size = "1MiB"

[native]
link = ["host.o"]
libraries = ["sqlite3"]
search = ["vendor"]
```

| セクション | キー | 意味 |
| --- | --- | --- |
| `[package]` | `name`、`version`、`namespace` | パッケージ名、版、既定の名前空間。名前空間は `::` でつないだ識別子で、16 セグメント、255 バイトまで。`std` や標準ライブラリのモジュール名では始められません |
| `[dependencies]` | `<名前> = { path = "相対パス" [, native = true] }` | ローカルパス依存のみ対応（最大 1024 個）。`git` や版の指定は `E0002`。`native = true` を指定すると、依存側の `[native]` をこのルートのリンクへ含める |
| `[wasm]` | `max-memory`、`stack-size` | 文字列のサイズ。コマンドラインが省略したときの既定。ルートパッケージだけが効きます |
| `[native]` | `link`、`libraries`、`search` | 文字列の配列。各キーは 1 行。パスはパッケージからの相対パスで、絶対パスは不可 |

依存のモジュールは、依存先の名前空間を付けて参照します。名前空間の規則は [言語仕様のローカルパッケージ](../../../docs/language.md#ローカルパッケージ) と [パッケージ](../organizing-tsuzuri/packages.md) を見てください。

`[wasm]` のサイズが不正だと、コマンドラインが正しくても終了コード 1 です。メッセージには `(after applying the root package's [wasm])` が付きます。コマンドラインに同じ値を書くと、そちらが優先され、マニフェストの値は使いません。

`[native]` は、ネイティブ実行ファイルをリンクする `build`、`run`、`test` でだけ効きます。オブジェクトや WASM では無視ではなく、そのコマンドがリンク入力を受けないので、コマンドライン側と同じく拒否されます。並びはマニフェストが先、コマンドラインがあとです。

## コマンドラインで分ける

ターゲット、最適化、デバッグ情報、allocator は、ソースに書きません。同じ `Main.tz` を、native と wasm32 の両方へ出せるようにするためです。

```sh
tsuzuri build Main.tz --target wasm32 --wasm-max-memory 64MiB -o shop.wasm
tsuzuri build Main.tz -o shop
```

フラグの組み合わせと既定は [コンパイラ オプション](option.md) にあります。ソースを変えずに成果物だけを変えるのが、指令の代わりです。

## 警告を失敗にする

`#nowarn` に当たる、警告コードを 1 つ消す構文はありません。未使用のローカルは、名前を `_` か `_name` にすると `W1001` が出なくなります。配列の暗黙コピー `W1006` は、既定では出さず、`--warn implicit-copy` を付けたときだけ出ます。

警告をビルドの失敗にしたいときは、`--deny-warnings` です。`check`、`build`、`run` に加え、実装上は `doc` と `test` の前にも効きます。警告が 1 つでもあれば終了コード 1 で、コード生成や実行には進みません。既存の成果物は残ります。

```text
./Main.tz:2:9: warning[W1001]: unused local 'unused'; prefix it with '_' to silence this warning
  2 |     let unused = 1
    |         ^
```

この警告だけの `check` は終了コード 0 ですが、`--deny-warnings` を付けると終了コード 1 になります。`--json` でも重要度は `warning` のままです。エラーがあるファイルでは、警告は出しません。

シャドーイングの `W1004` は、コンパイラ内部の検査用で、コマンドラインからは出せません。ユーザーが付ける公式の警告フラグは `--warn implicit-copy` だけです。

## 他の言語との比較

| やりたいこと | C / C++ | C# / F# | Tsuzuri 0.1.0 |
| --- | --- | --- | --- |
| ターゲットでソースを分ける | `#if` | `#if` / 条件付きコンパイル | 別の `--target`。使えない API はエラー |
| 警告を 1 つ消す | 診断プラグマ | `#nowarn` | 無い。未使用は `_` 接頭辞。全体は `--deny-warnings` |
| 定数を畳む | マクロや `constexpr` | `const` / リテラル | `const` または `@literal` |
| CPU ごとの実装 | 組み込み関数と `#ifdef` | ランタイムの分岐が中心 | `@cpu` と、実行時の 1 回の選択 |

## まとめ

- `#if` も `#nowarn` もありません。`#` で始めても指令にはなりません。
- 定数、溢れる算術、CPU の版は、属性としてソースに書きます。
- パッケージ、依存、WASM のサイズ、ネイティブのリンクは `Tsuzuri.toml` の 4 セクションです。
- ターゲットと最適化はコマンドラインに残し、ソースを分岐させません。
- 警告を失敗にする公式のスイッチは `--deny-warnings` だけです。
