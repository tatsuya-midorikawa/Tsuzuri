# 知識グラフ

`tsuzuri check`・`build`・`run`・`test` は、プロジェクトを解析するたびに、その**知識グラフ**（KG）をプロジェクトの `target/tz/kg/` に書きます。知識グラフは、コンパイラが型検査と所有権解析で得た事実（宣言、呼び出し、型の使用、効果、トラップ箇所、所有権の出来事、型のレイアウトなど）を、宣言を**ノード**、宣言どうしの関係を**辺**とするグラフにしたものです。AI や道具は、ソースを探して読み直さずに、この表と、そこから作った短い英語の要約（brief カード）からプロジェクトを読み始められます。ファイルの各行の形は [知識グラフの形式](kg-format.md) にあります。

## この記事のポイント

- プロジェクト（`Tsuzuri.toml` か `Main.tz` のある根）の `check`・`build`・`run`・`test` が書きます。単独のファイルは `--kg` を付けたときだけです。`--no-kg` か `TSUZURI_KG=0` で書きません。
- ソース・マニフェスト・コンパイラが前回と同じなら、何も書き直しません（2 回目の `check` はファイルに触れません）。
- 書けないとき（置き場が知識グラフでない、書き込めないなど）は警告 1 行（`W2001`）だけで、診断と終了コードは変わりません。
- 同じソースと同じコンパイラからは、どの機械・どのディレクトリでも、名前が `.` で始まらないファイルが byte 単位で同じになります。
- `tsuzuri kg build|verify|clean|export` で、明示的に作る・確かめる・消す・出力できます。

## 置き場とファイル

| パス | 中身 |
| --- | --- |
| `.tsuzuri-kg` | マーカー（2 行。`generated by tsuzuri kg` とコンパイラの stamp）。機械ごとのファイル |
| `manifest.json` | schema（`tz-kg/1`）・コンパイラ・edition・プロジェクトの名前と版・解析が成功したか（`complete`）・入力のハッシュ（`source_hash`）・件数・モジュール・各ファイルの SHA-256 |
| `nodes.jsonl`・`edges.jsonl` | ノード（宣言）と辺（`contains`・`calls`・`uses_type`・`implements`・`instance_of`・`imports`・`tested_by`） |
| `tests.jsonl` | テストとベンチマーク（`tsuzuri test --index` の番号） |
| `facts/<モジュール>.jsonl`・`layout/<モジュール>.jsonl` | 関数の事実と型のレイアウト（行のあるモジュールだけ） |
| `diag.jsonl` | 解析の診断（`check --json` と同じ形。パスは根からの相対。`--warn implicit-copy` の `W1006` は入れない） |
| `brief/L0.md`・`brief/L1/<モジュール>.md`・`brief/L2/<ID>.md` | 要約カード（プロジェクト・モジュール・宣言） |

置き場は `--kg-dir DIR`、次に `TSUZURI_KG_DIR`、どちらもなければ `<根>/target/tz/kg` です（`Tsuzuri.toml` のあるプロジェクトの根は、そのマニフェストのディレクトリです）。ファイル名は、モジュールの key か ID の `::` を `.` にし、英数字・`_`・`.` 以外の文字を `%XX` にしたものです。200 バイトを超える名前は、先頭の 183 バイト（`%XX` の途中では切らない）に `-` と ID の SHA-256 の先頭 16 桁を続けたものになります。`tsuzuri new` の `.gitignore` は `target/` を除外します。ソースを探すとき、マーカーのあるディレクトリは読みません。

型検査の通らないプロジェクトの知識グラフは、マーカー・`manifest.json`（`complete: false`）・`diag.jsonl` だけです。前の事実を残して、今のソースの事実のように見せることはしません。

## 書き直すとき

`check` などは解析の前に、置き場の `manifest.json` とマーカーを読みます。次がすべて前回と同じなら、何も書かず、解析も知識グラフの分の仕事をしません。

- 入力のハッシュ（利用者と依存パッケージの `.tz`・`.tt`・`.tc` と、`Tsuzuri.toml`・`Tsuzuri.lock` の内容、ソースの既定の名前空間。マニフェストのないプロジェクトではディレクトリの名前が名前空間なので、ディレクトリの名前を変えても書き直します）
- schema（`tz-kg/1`）とコンパイラの版
- マーカーの stamp（その機械のコンパイラの実行ファイルの識別。開発中に作り直したコンパイラを見分けます）

書くときは、置き場の隣の一時ディレクトリにすべてを書いてから、ディレクトリごと入れ替えます。読み手は `manifest.json` に載ったファイルだけを読み、どのファイルも `manifest.json` の SHA-256 と一致することを確かめます。読む途中で知識グラフが入れ替わって一致しなければ初めから読み直す（3 回まで）ので、読み手が見るのは、前の知識グラフか、ないか、新しい知識グラフのどれかで、混ざることはありません。載っているファイルがない・一致しない・置き場の外を指す（`..` やリンクのディレクトリ）ときは `kg_broken` です。同時に複数のプロセスが書いても壊れません。マーカーのないディレクトリは決して上書きしません。

## brief カード

カードは決定的な英語の要約で、文字数（Unicode の scalar の数）の上限があります。上限を超えるときは、優先度の低い行から `…N more` に置き換えます。

| カード | 上限 | 内容 |
| --- | --- | --- |
| `L0.md` | 2,400 | プロジェクト: 規模（モジュール・ノード・辺・テストの数）、入口、モジュールの要約、`export`、モジュールの依存、テストの数、効果 |
| `L1/<モジュール>.md` | 1,600 | モジュール: 型（メンバー）、関数（呼び出し元の数と効果）、instance、テスト、使う・使われるモジュール |
| `L2/<ID>.md` | 700 | 宣言: 署名、引数の渡し方、説明の 1 行目、効果、トラップ・確保・複製の箇所の数、再帰、呼び先・呼び出し元・テスト（型は使う宣言） |

L2 のファイルは、`export`、公開、非公開の順に 256 件までです。残りは `manifest.json` の `l2_omitted` に数えます。

```text
# Acme::Shop::Cart (Cart.tz)
3 items, 3 public | 2 tests

## Types
- record Line {sku, quantity, unit_price}

## Functions
- def line_total :: ref Line -> i64 | callers 2
- def total :: ref [Line] -> i64 | callers 3

## Tests
- line total
- empty cart

used by: Acme::Shop::Main, Acme::Shop::Report
```

## `tsuzuri kg`

```text
tsuzuri kg build  [PATH] [--kg-dir DIR] [--force] [--json]
tsuzuri kg build  --std [--force] [--json]
tsuzuri kg verify [PATH] [--kg-dir DIR] [--json]
tsuzuri kg clean  [PATH] [--kg-dir DIR] | kg clean --std
tsuzuri kg export [PATH] [--kg-dir DIR] (--nodes | --edges | --facts) [--no-refresh]
```

`PATH` は `check` と同じ入力（ディレクトリかファイル。既定は `.`）で、`Main.tz` がなくても構いません。`kg` は `--kg`・`--no-kg`・`TSUZURI_KG` を読みません。

| コマンド | 動き | 出力 | 終了コード |
| --- | --- | --- | --- |
| `build` | 古ければ解析して書く（`--force` は新しくても書き直す）。解析の診断は `check` と同じに標準エラーへ | `kg: wrote N files to DIR`・`kg: up to date (DIR)`・`kg: incomplete, N errors (DIR)` | 0。エラーのあるプロジェクトは 1 |
| `verify` | 新しさ、全ファイルの SHA-256、グラフの不変条件（ID が一意、辺の始点がノード、`contains` がモジュールを根とする森）を確かめる | `kg: ok (N nodes, N files, source 先頭 12 桁)` | 0。違えば `E2009` で 1 |
| `clean` | マーカーのある置き場を消す | なし | 0。マーカーのないディレクトリは `E2009` で 1 |
| `export` | 古ければ作り直し（`--no-refresh` では作らない）、`nodes.jsonl`・`edges.jsonl`・`facts/*.jsonl` をそのまま標準出力へ | JSON Lines | 0。ないか不完全は `E2009` で 1 |

`--json` の `build` は `{"type":"kg_build","status":"written","dir":"…","files":19,"complete":true}`（`status` は `written`・`unchanged`・`incomplete`。エラーのあるプロジェクトの知識グラフが前回のままなら、書かずに `incomplete`・`"files":0`・`"complete":false` で、終了コードは 1）、`verify` は `{"type":"kg_verify","status":"ok","source_hash":"…","nodes":14,"files":17}` を 1 行出します。

```sh
tsuzuri kg build
tsuzuri kg verify --json
tsuzuri kg export --edges | grep '"rel":"calls"'
```

### E2009

| kind | いつ |
| --- | --- |
| `kg_missing` | 置き場がない（マーカーのないディレクトリがあるときは「no .tsuzuri-kg marker」） |
| `kg_stale` | ソースが変わった・別のコンパイラ・別の schema |
| `kg_broken` | `manifest.json` が読めない、ファイルの欠落・不一致、グラフの不変条件の違反 |
| `kg_not_ours` | 置き場が知識グラフでないか、プロジェクトのソースを含む |
| `kg_incomplete` | 型検査の通らないプロジェクトの知識グラフ |

## 標準ライブラリの知識グラフ

プロジェクトの知識グラフは std を含みません。std の宣言は、コンパイラのキャッシュ（`TSUZURI_CACHE_DIR`）の `kg-std/<コンパイラの識別>/` に 1 つだけあります。`tsuzuri kg build --std` で作り、照会が std の ID（`Array.map` など）を必要としたときにも作ります。行の `origin` は `std`、ID は名前空間なしです。新しい 3 世代を残し、古いものは消します。`tsuzuri kg clean --std` で全部消せます。キャッシュがないとき、または書かない読み手（MCP など）は、メモリの上に作ります。

## 増分について

ソースのどれかが変わると、知識グラフは全部を作り直します。モジュールごとの事実の書き出しを再利用する増分は実装していません。200 モジュールの合成プロジェクトで測ると、事実とレイアウトの書き出しとハッシュは知識グラフの生成時間の約 3% で、再利用しても縮むのはそこだけだからです（設計の前提である 10% に届きません）。時間の大半は、ファイルの作成（約 860 ファイルで約 100 ms）です。
