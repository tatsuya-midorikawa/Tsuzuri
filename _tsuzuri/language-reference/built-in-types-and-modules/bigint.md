# BigInt

`bigint` は、メモリが許す限り桁を伸ばせる符号付き整数です。標準ライブラリの不透明レコード `BigInt` と同じ型で、`123I` のように `I` 接尾辞のリテラルで書きます。固定幅の [`Int`](int.md) では溢れる積や、ID や金額の桁が最初から分からない値に使います。

中身は 10 億進法（$10^9$ 進法）の桁配列です。筆算に近いアルゴリズムで演算するため、桁数が増加するにつれて乗算や除算の処理コストが大きくなります。

## この記事のポイント

- 型名は注釈では `bigint`、関数シグネチャでは `BigInt` と書きます。同じ型です。
- `+`、`-`、`*`、`/`、`%`、`**` と比較が使えます。ゼロ除算と、負の指数や巨大な指数はトラップします。
- Copy 型です。演算のたびに桁配列が複製され得ます。フィールドは外から見えません。
- 文字列との往復は 10 進だけです。`0x` や `+` は解析に失敗して `None` になります。

## 固定幅に収まらない積

```tsuzuri run=19999999999999999999999999999
let price = 9999999999999999999999999999I
let doubled = price * 2I + 1I
let quotient = -7I / 2I
let remainder = -7I % 2I
let power = 2I ** 100
let back = BigInt.to_i64 ref power
assert (Maybe.is_none ref back)
assert (quotient == -3I && remainder == -1I)
assert (power > price)
doubled
```

実行結果:

```text
19999999999999999999999999999
```

`2I ** 100` の指数 `100` は、`**` が `bigint` を期待するので接尾辞がなくても `bigint` になります。結果は `i64` に収まらないため、`BigInt.to_i64` は `None` です。トップレベルの値は 10 進のまま表示されます。引用符は付きません。

`/` はゼロ方向への切り捨て、`%` は被除数と同じ符号です。`-7 / 2` は `-3`、余りは `-1` です。固定幅の整数と同じ規則です。

## リテラルと型名

接尾辞 `I` は 10 進でも `0x` や `0b` でも使えます。`0xFFI` は 255 です。小数点や指数表記に `I` は付けられません。

`bigint` が期待される位置では、接尾辞のない整数リテラルもその型になります。

```tsuzuri run=5
let noted: bigint = 2
let named: BigInt = 3I
noted + named
```

実行結果:

```text
5
```

関数の `::` 型シグネチャでは注意が必要です。小文字の `bigint` を型名として記述すると（例: `def f :: bigint -> bigint`）、コンパイルエラー `E1004`（型が見つからない）になります。シグネチャにはレコード名である `BigInt` を記述してください。なお、`let` の型注釈では `bigint` と `BigInt` のどちらも使用できます。

```text
def twice :: BigInt -> BigInt
fn twice value = value + value
```

このシグネチャは構文の抜粋ではなく、後の節の実行例でもそのまま使用しています。`:: bigint` と書いた場合のみエラーとなります。

## 演算子

| 演算 | 意味 | 失敗 |
| --- | --- | --- |
| `+`、`-`、`*`、単項 `-` | 任意精度の加算・減算・乗算・符号反転 | メモリ不足は言語トラップ |
| `/` | ゼロ方向への切り捨て除算 | ゼロ除算はトラップ |
| `%` | 被除数と同じ符号の剰余 | ゼロ除算はトラップ |
| `**` | 二乗法の累乗。指数 0 は 1 | 負の指数、または指数が `10^18` 以上ならトラップ |
| `==`、`!=`、`<`、`<=`、`>`、`>=` | 符号と大きさを見る | 失敗しない |

`**` は右結合で、`*` より強く結合します。指数の上限は、内部の桁が 10 億進法で 2 桁まで、つまり `10^18` 未満です。これを超えるとアサーションでトラップし、`None` にはなりません。

ビット演算、シフト、`Int.checked_add` のような検査付き API はありません。溢れたら `Maybe` が欲しい計算は、固定幅の [`Int`](int.md) を使う場面です。

`as i64` などのキャスト演算子はサポートされていません。範囲を確認しながら `i64` へ変換するには `BigInt.to_i64` を使います。

## 公開関数

`std/BigInt.tz` が公開している関数は次の 4 つです。演算子は型クラスのインスタンスとして提供されており、モジュール関数ではありません。

| 関数 | シグネチャ | 説明 |
| --- | --- | --- |
| `BigInt.of_i64` | `i64 -> BigInt` | `i64` を `bigint` に変換。常に成功する |
| `BigInt.to_i64` | `ref BigInt -> Maybe<i64>` | 範囲外なら `None`。引数の値は消費しない |
| `BigInt.of_string` | `ref string -> Maybe<BigInt>` | 省略可能な `-` と 10 進数字を解釈。不正な文字列は `None` |
| `BigInt.compare` | `ref BigInt -> ref BigInt -> i64` | 小さい、等しい、大きいを `-1`、`0`、`1` で返す |

引数に `ref` を連続して渡すときは括弧で囲む必要があります（例: `BigInt.compare (ref left) (ref right)`）。括弧を省略して `BigInt.compare ref left ref right` と書くと構文エラー `E0002` になります。

```tsuzuri run=-1200
let parsed = BigInt.of_string ref "-1200"
let bad = BigInt.of_string ref "+12"
let hex = BigInt.of_string ref "0x10"
assert (Maybe.is_none ref bad)
assert (Maybe.is_none ref hex)
Maybe.get parsed
```

実行結果:

```text
-1200
```

`Parse.parse` も同じ規則です。前後の空白、`+`、`0x`、`0b`、桁区切りの `_` は受け付けません。失敗してもトラップしません。

表示は `Display` と `to_string` です。ゼロは `"0"`、負数は `-` のあとに数字が続きます。下位の桁は 9 桁になるまで `0` で埋めます。指数表記にはしません。

`Hash` と `Default` もあります。`Default` は `0` です。今の `Hash` は、FNV-1a の 64 bit 定数で桁を混ぜ、負数ならビットを反転します。マップのキーには使えます。版をまたいで同じビット列とは限りません。

## 所有権

`BigInt` は Copy 型です。次のように、渡したあとも元の変数を使えます。

```tsuzuri run=3
def twice :: BigInt -> BigInt
fn twice value = value + value

let unit = 1I
twice unit + unit
```

実行結果:

```text
3
```

Copy 型ですが、複製コストが常に軽量であるとは限りません。値のコピーに伴って内部の桁配列も複製されます。`+` や `*` などの演算子は値を受け取るため、巨大な桁数の値を頻繁に計算すると複製のオーバーヘッドが無視できなくなります。比較や範囲判定のように値を消費する必要がない処理では、`BigInt.compare (ref left) (ref right)` や `BigInt.to_i64 (ref value)` のように借用を活用してください。

```mermaid
flowchart LR
  lit["123I または注釈 bigint"]
  lit --> value["Copy 型の値"]
  value --> ops["演算子は値を受け取る"]
  value --> borrowed["compare と to_i64 は ref"]
  ops --> digits["桁配列が複製され得る"]
```

レコードの中身は不透明です。`value.limbs` のようにフィールドを読むと `E1022` になります。パターン分解やレコード更新もできません。外から使えるのは、このページの演算子と関数だけです。

## 性能の注意

内部表現は符号と、10 億（$10^9$）を基数とする `i64` 配列です。加算は桁数 $O(N)$ に比例し、乗算は筆算（$O(N \times M)$）、除算も筆算による長除算です。Karatsuba 法や FFT による高速乗算アルゴリズムは採用していません。

そのため、数万〜数百万桁に達する暗号演算や巨大科学計算よりも、通常の固定幅整数では溢れてしまう金額、累乗計算、あるいは識別番号などをオーバーフローの心配なく安全に扱う用途に適しています。桁が `i64` や `i128` に収まる範囲であれば、固定幅の [`Int`](int.md) を使用する方が高速かつ効率的です。

メモリが確保できないときの失敗は言語トラップです。`Result` にはなりません。トラップ時に未実行のデストラクタは走りません。

## 他の言語との比較

| 点 | Tsuzuri | Rust | Python |
| --- | --- | --- | --- |
| 書き方 | `123I`、または注釈 `bigint` | 標準にはない。クレートを使う | 整数リテラルがそのまま任意精度 |
| ゼロ除算 | トラップ | クレートによる | `ZeroDivisionError` |
| 所有 | Copy。桁配列は複製され得る | 多くの実装はクローンが明示 | 参照カウント |
| 中身 | 不透明。10 億進法 | 実装による | 実装依存 |

## まとめ

- `123I` と `let n: bigint = 2` で作れます。関数シグネチャには `BigInt` と書きます。
- 除算の切り捨てと余りの符号は、固定幅の整数と同じです。
- 解析に失敗したら `None`、ゼロ除算と不正な指数はトラップです。
- Copy ですが、大きな値の複製コストは無視できません。比較は `ref` で足ります。
- フィールドには触れません。
